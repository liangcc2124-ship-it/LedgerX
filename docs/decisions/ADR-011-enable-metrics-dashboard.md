# ADR-011：在基础账本之上启用指标、公式与财务总览

- 状态：已接受
- 日期：2026-09-15
- 决策者：产品用户与高级设计阶段
- 替代范围：[ADR-010](./ADR-010-basic-ledger-scope.md) 中关于“指标/公式/仪表盘继续延后”的部分；ADR-010 对基础记录、资产、分摊、应付款、报表、预警、备份和商业发布的其他裁决继续有效

## 背景

基础记账闭环已经固定为收入、固定支出、弹性支出、分类、账户、余额与回收站。用户现在明确要求在财务总览中添加系统和自定义指标，以安全公式计算，并支持日、周、月、年四种时间层级以及桌面卡片的自由拖动、缩放和布局保存。

仓库中的旧 C#/React 版本具有公式和布局原型，但目标产品已经迁移到 Java 11 + Vue 3 + Electron + SQLite。旧实现只能作为行为样本，不能恢复进程内 bridge、JSON 全量快照或前端财务计算。

## 决策

1. 当前目标范围新增 `metrics-formulas-dashboard` 能力，包括系统指标、自定义计算指标、公式版本、公式校验/预览、总览聚合和每个 profile 的桌面布局。
2. 日、周、月、年是同一财务总览的时间粒度。四种粒度共享一份桌面布局，只替换期间、比较区间和趋势分桶；首屏默认当前月。
3. 收入和支出按 `occurred_on` 归属期间；现金流和账户余额按 `settlement_on` 归属。余额类指标计算到所选期间的 `asOf`，当前/未来期间不得使用今天之后的事实。
4. 自定义公式可引用系统/自定义指标、分类收入、分类支出、账户余额和白名单时间变量。引用在持久化 AST 中保存稳定 ID，显示名称变化不能破坏公式。
5. 公式只接受白名单 AST；不执行 JavaScript、SQL、反射、脚本、文件或网络调用。前端以中文函数名、中文说明和结构化引用编辑，API 使用稳定的规范节点与函数标识。
6. 指标值、比较值和趋势序列由 Java 在读取时计算，Vue 不下载全量记录自行求和。第一版不持久化指标计算缓存。
7. 布局使用 12 列桌面网格，只在显式“编辑布局”模式中拖动和缩放。卡片有内容决定的最小尺寸，不承诺任意缩小；任何尺寸层级都不能裁掉其实际展示的关键内容。
8. 本轮不启用 `direct_metric_entry`、`record_metric_assignment`、固定资产、分摊、应付款、报表或预警。没有真实数据链路的历史指标不得伪装成可用指标。
9. 指标/公式/布局使用新的前向 SQLite migration 添加，不能修改已经执行的 V001–V004。系统指标及默认可见性由确定性 seed 建立。

## 关键口径

- 周从周一开始，到下周一结束；全部业务日期使用后端本地 Windows 时区和可替换 `Clock`。
- 当前期间 `asOf=min(今天, endExclusive-1天)`；历史期间使用 `endExclusive-1天`。完全位于未来的期间返回空数据状态，不伪造零趋势。
- 环比基础对象是紧邻的前一个同粒度自然期间。历史完整期间比较完整上一期；当前尚未结束的 WEEK/MONTH/YEAR 只比较上一期相同已过自然日数（受上一期实际长度限制），避免用本月至今对比完整上月。DAY 因没有日内时间事实，仍比较完整前一日。上一比较窗分母为零时，变化率为 `null`，但仍返回上一窗原值。
- 分类引用包含所选分类及其当前后代；分类改名不改变公式，重新归类会有意重算历史报表。
- 账户余额引用按账户自身余额方向和截至 `asOf` 的活动记录投影；已归档账户仍可供已保存公式计算，但不能从新公式选择器中新建引用。

## 后果

正面结果：总览不复制财务规则；四级视图、公式和卡片使用同一聚合契约；重命名不会破坏公式；历史期间可以按当前公式重算；功能仍保持本地模块化单体。

代价：需要新增 schema、领域聚合、公式依赖图、Dashboard API、Vue 公式编辑器和布局交互；记录变化会使结果在下次读取时重算。若 20,000 条样本下不能达到性能门槛，再以测量结果决定派生缓存，不提前增加缓存失效复杂度。

## 被拒绝方案

- **恢复旧 C#/React 实现**：与目标架构和持久化边界冲突。
- **前端加载全部记录后计算**：会复制业务规则、扩大响应并造成页面结果不一致。
- **保存公式原始 JavaScript/SQL**：无法建立安全、依赖和可迁移边界。
- **四个视图分别保存布局**：初期增加四倍状态且切换体验不稳定；无真实需求前共用布局。
- **同时恢复全部高级财务域**：超出当前数据输入能力和用户本轮目标。

## 重新评估触发器

- 用户需要手工录入非现金指标值或把一条记录归集到多个指标时，重新设计 direct metric/assignment 的输入、事务和列表投影。
- 用户需要固定资产、应付款、分摊、预警或正式报表时，分别恢复对应模块，不把占位字段视为已实现能力。
- 20,000 条记录的总览读取持续超出已接受门槛时，先分析 SQL、依赖图和序列化，再决定缓存或派生表。
- 用户要求四种时间粒度拥有不同布局时，在 layout key 中增加 granularity，并提供兼容迁移。
