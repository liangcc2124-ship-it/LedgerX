# LedgerX v2.1 迭代建议

> 状态：已由 LedgerX-v2.1-正式迭代需求文档.md 取代；后续开发以正式文档为准。

- 建议版本：v2.1.0
- 迭代主题：数据可带走、可恢复、可清空，日常记录可纠错
- 产品边界：单用户、手动维护、Windows 本地优先、不建设云服务
- 基线版本：v2.0.0

## 1. 结论先行

v2.0 已经具备“能记录、能计算、能展示”的完整骨架，但下一版不宜立刻堆预算、公式编辑器或复杂图表。当前最值得解决的是数据生命周期与日常纠错：换电脑时用户要有把握，恢复前要知道会发生什么，录错一笔后要能修改，想重新开始时也不必去资源管理器寻找文件。

因此，建议把 v2.1 定义为“可靠性版本”，核心目标是：

1. 用户能在应用内完成迁移、恢复、清空和定位数据。
2. 所有危险操作都有预览、自动保护和明确反馈。
3. 记录可以编辑、撤销删除和按条件查找。
4. 备份文件具有版本信息，未来升级不靠运气兼容。
5. 指标明确统计周期，避免把累计值误当成本月状态。
6. 从同一套账本与指标生成日报、周报、月报和年报。
7. 用户可以为任意可计算指标建立本地财务预警。

## 2. 当前最需要改进的地方

### 2.1 数据迁移流程不够完整

当前已有 JSON 导出和恢复，但缺少备份内容预览、备份时间、来源版本、恢复前自动快照和恢复结果摘要。用户面对一个 JSON 文件时无法判断它是不是正确账本，也不知道恢复会覆盖多少记录。

建议：

- 备份加入格式版本、LedgerX 版本、创建时间、记录数、自定义指标数和数据校验摘要。
- 恢复前展示备份信息和影响范围。
- 恢复前自动创建当前账本快照。
- 恢复失败时保持原数据不变，并提供错误原因。
- 同时兼容 v1/v2 已经导出的旧 JSON 文件。

### 2.2 缺少应用内清空数据

目前只能手动删除 LocalAppData 中的 ledger.json。这个动作对普通用户不够友好，也容易误删整个目录。

建议将清理拆成两个动作：

- 清空账本：删除记录和自定义指标，保留皮肤及界面偏好。
- 恢复出厂状态：清空账本并重置所有偏好。

两者都必须：

- 明确列出将删除的内容。
- 默认先生成一份可恢复快照。
- 要求输入“清空 LedgerX”完成二次确认。
- 完成后展示清理结果，而不是只让页面突然归零。

### 2.3 记录只能新增或删除，不能纠错

手动记账最常见的操作不是删除，而是修正金额、日期、分类或记录类型。当前删除后重录成本较高，也容易改变原记录顺序。

建议：

- 支持编辑已有记录。
- 保存前展示指标影响变化，例如“现金储备将减少 20 元”。
- 删除改为进入本地回收站，默认保留 30 天。
- 删除后提供短时“撤销”入口。
- 保留 createdAt，并增加 updatedAt，便于审计和排错。

### 2.4 指标缺少统计周期

固定成本、可变成本和净现金流目前主要按累计数据计算。随着记录增多，累计值会越来越难用于判断当月财务状态。

建议：

- 总览增加“本月 / 上月 / 今年 / 全部”周期选择。
- 现金储备、总资产和应付账款属于时点值，不随周期错误归零。
- 收入、成本和净现金流属于期间值，按所选周期重新计算。
- 每张指标卡显示口径，例如“本月累计”或“截至今天”。
- Runway 使用最近完整月份的平均消耗，并在样本不足时明确提示。

### 2.5 财务依赖度的分类方式过于脆弱

当前通过分类名称是否包含“父母”估算财务依赖度。改成“家里转账”后就可能无法识别。

建议：

- 给收入记录增加来源属性：父母支持、奖学金、兼职、实习、投资、其他。
- 增加“自主收入”布尔属性或来源分组。
- 财务依赖度从结构化字段计算，不再依赖文字匹配。
- 旧记录继续兼容，并允许批量补充来源。

### 2.6 数据管理页缺少状态反馈

目前数据页只显示路径和两个按钮，不能回答“上次什么时候备份”“现在有多少数据”“文件是否健康”。

建议显示：

- 当前账本记录数、自定义指标数和文件大小。
- 最近保存时间与最近备份时间。
- 数据文件位置及“打开所在文件夹”按钮。
- 数据完整性检查结果。
- 当前应用版本与备份格式版本。

### 2.7 异常恢复与诊断仍然偏技术化

LedgerStore 已会保存损坏文件副本，但用户无法在界面中了解发生了什么。WebView2 Runtime 缺失或资源加载失败时，也需要更清楚的解决入口。

建议：

- 检测到账本损坏时展示恢复页，不直接以空账本代替。
- 展示损坏副本路径、最近可用备份和“打开数据目录”。
- WebView2 缺失时给出安装说明，而不是泛化的加载失败。
- 增加本地诊断日志，但禁止写入具体金额、分类和备注。

### 2.8 缺少周期化财务报告

当前“财务分析”只展示即时判断，无法形成可回顾、可比较的日报、周报、月报和年报。下一版应将财务分析升级为“报告与分析”，报告全部从已有记录和指标实时生成，不要求用户重复填写。

#### 日报

日报回答“今天发生了什么”，至少包含：

- 当日现金流入、现金流出和净现金流。
- 当日固定成本、可变成本和固定资产购置。
- 新增及已支付的应付账款。
- 当日记录明细、主要分类和最大单笔变化。
- 与昨日相比的现金储备变化。
- 无记录时明确显示“今日暂无记录”，不能伪造趋势。

#### 周报

周报回答“这一周的节奏是否正常”，默认按周一至周日统计，并允许用户切换自然周：

- 本周现金流入、现金流出、净现金流及上周对比。
- 本周固定成本、可变成本、主要分类和最大单笔变化。
- 7 天每日净现金流柱形图，并标出异常日期。
- 本周成本分类 Top 5 排序条形图。
- 下周七天内已知应付账款和预计固定成本提示。
- 周初与周末现金储备变化。
- 当前周尚未结束时明确显示“截至今天”，不得与完整上周直接误导性比较。
- 一周有效日期不足时使用 KPI 与每日列表，不强行绘制趋势线。

#### 月报

月报回答“这个月的钱是怎么运转的”，至少包含：

- 月度流入、流出、净现金流及环比。
- 固定成本、可变成本和成本结构。
- 收入来源结构、财务依赖度和自主收入占比。
- 月初与月末现金储备、总资产和应付账款变化。
- Burn Rate、Runway 和安全垫状态。
- 主要变化来源、异常大额记录和本月总结。
- 支持切换月份，并与上月或去年同月比较。

#### 年报

年报回答“这一年整体变好还是变坏”，至少包含：

- 全年收入、成本、净现金流和月均现金消耗。
- 12 个月趋势以及最高、最低月份。
- 年初与年末现金、固定资产、应付账款和总资产变化。
- 收入集中度、财务依赖度和自我造血能力变化。
- 固定成本与可变成本的年度结构。
- 全年主要财务事件和年度总结。
- 支持切换年份；数据不足时只展示有依据的结论。

#### 共同规则

- 日报、周报、月报和年报必须使用同一套底层记录和指标计算器。
- 每个数字都能下钻到组成它的记录。
- 报告显示统计范围、生成时间、指标口径和数据完整性提示。
- 全局及单指标隐私设置同样作用于报告。
- 修改、删除或恢复记录后，相关报告立即重算。
- v2.1 先提供应用内查看；打印或导出 PDF 作为 P1，不阻塞核心报告发布。
### 2.9 报告需要真正的可视化层

日报、周报、月报和年报不能只是数字卡片加一段文字。可视化的目标是帮助用户识别变化、结构和异常，每张图必须回答一个明确问题，并保留查看精确记录的入口。

#### 图表地图

| 报告 | 要回答的问题 | 推荐图表 | 数据要求与降级方案 |
| --- | --- | --- | --- |
| 日报 | 今天的现金为何变化 | 现金变动瀑布图：期初现金 + 流入 − 流出 = 期末现金 | 加减项必须能闭合；否则改为 KPI 卡与记录列表 |
| 日报 | 最近一段时间是否出现异常 | 最近 14 天净现金流柱线组合或单序列柱形图 | 少于 8 个有效日期时改为每日数值列表 |
| 日报 | 今天的钱主要花在哪里 | 排序水平条形图 | 至少 4 个分类；分类过少时使用紧凑排行 |
| 周报 | 本周每天的现金变化如何 | 7 天净现金流柱形图 | 固定显示周一至周日；未来日期留空，不当作零 |
| 周报 | 本周与上周差异多大 | 本周/上周分组条形图或带基准点图 | 当前周未结束时按相同已过天数比较并明确标注 |
| 周报 | 本周成本集中在哪里 | Top 5 排序水平条形图 | 分类少于 4 个时改用紧凑排行 |
| 月报 | 本月现金流如何变化 | 按日折线图，显示流入、流出和净现金流 | 以自然日为粒度；无记录日期补零并明确口径 |
| 月报 | 成本由什么组成 | 固定成本与可变成本堆叠条形图 | 显示金额和占总成本比例；分母为零时不画占比 |
| 月报 | 哪些分类影响最大 | Top 5 排序水平条形图，其余合并为“其他” | 保留总额和长尾入口，不用彩虹色区分类别 |
| 月报 | 与上月相比改变了什么 | 本月/上月分组条形图或带基准的点图 | 只比较同口径完整周期；本月未结束时标注“截至今日” |
| 年报 | 全年趋势如何 | 12 个月流入、流出和净现金流折线图 | 12 个自然月；不足 8 个月时改用月度柱形图 |
| 年报 | 成本结构是否改变 | 月度固定/可变成本堆叠柱形图 | 使用统一纵轴与单位，不截断绝对值柱形图零基线 |
| 年报 | 收入是否过度集中 | 收入来源排序条形图及集中度标记 | 展示来源金额、占比和总收入分母 |
| 年报 | 资产与负债如何演变 | 月末资产、现金与应付账款趋势图 | 只使用月末快照；没有可靠快照时显示首末值和说明 |

#### 可视化设计原则

- KPI 卡用于精确状态，图表用于趋势、比较和结构，两者不重复抢占空间。
- 时间趋势默认使用折线图；分类比较默认使用排序条形图；组成关系优先堆叠条形图。
- 饼图不作为默认选择。分类多时使用 Top N + 其他，避免切成一盘财务披萨。
- 金额柱形图从零开始；聚焦变化的瀑布图可以使用紧凑范围，但必须标注期初、期末和净变化。
- 单图最多使用暖铜主色、一个辅助色和中性色；不依赖红绿区分正负。
- 正负变化同时使用正负号、零线、明暗或实心/空心标记，保证灰度下仍能理解。
- 图表标题保持客观，例如“2026 年月度净现金流”；解释性结论放在图表下方。
- 副标题显示统计周期、单位、数据粒度和“截至今日”等口径信息。
- 图例能用直接标签替代时不单独展示，避免用户在图和图例之间来回找人。
- 所有图表使用 LedgerX 暖铜主题变量，皮肤切换后同步改变图表颜色。
- 禁止加载远程图表脚本、字体或数据；所有渲染与计算均在本机完成。

#### 交互与下钻

- 悬停或键盘聚焦时展示日期、金额、占比和比较值。
- 点击数据点或分类进入对应记录筛选结果。
- 支持切换日期、自然周、月份、年份及比较周期。
- 支持隐藏单个系列，但不能因此改变其他系列的计算口径。
- 图表与表格共享筛选状态，用户从图表下钻后可以返回原报告位置。
- 金额隐私模式开启时，坐标轴、提示框、标签和无障碍文本都必须隐藏具体金额，不能只遮住 KPI 卡。
- 提供“查看数据表”入口，满足精确查数和键盘、屏幕阅读器使用。
- 空数据、数据不足和分母为零分别展示明确状态，不生成看似完整的虚假趋势。

#### 技术建议

v2.1 建议使用 Recharts 的本地 npm 依赖构建 SVG 图表，封装统一的 ChartCard、ChartTooltip、EmptyChart 和 DrilldownFilter 组件。选择理由是与现有 React 界面集成简单、响应式和主题控制成本较低，并且不需要远程 CDN。

图表数据必须由 C# 指标与报告服务生成标准化数据集，React 只负责展示和交互。浏览器 Mock 与原生 WebView 必须使用同一份数据契约，避免测试通过但 EXE 口径不同。
### 2.10 缺少用户可配置的财务预警

报告负责回顾，预警负责在风险达到用户设定的条件时主动提醒。LedgerX 不替用户决定“多少钱才安全”，所有阈值、周期和严重程度均由用户设置；系统可以提供模板，但不得未经确认自动启用。

#### 规则结构

每条预警规则至少包含：

- 名称与说明。
- 是否启用。
- 监控指标：内置指标或自定义指标。
- 统计周期：当前值、当日、本周、本月、本年、滚动 N 天或滚动 N 个完整月。
- 比较方式：大于、大于等于、小于、小于等于、等于、变化超过、连续为负。
- 阈值及单位：金额、百分比、月份或普通数值。
- 可选比较基准：上一周期、最近 N 期平均值或用户目标值。
- 连续周期要求，例如“连续两个月净现金流为负”。
- 严重程度：提示、关注、严重。
- 重复策略：仅首次、每次满足、每天一次或冷却 N 天。
- 生效日期及可选失效日期。
- 提醒方式：应用内预警中心；Windows 系统通知列为可选能力。
- 隐私设置：通知中是否允许显示具体金额，默认不显示。

v2.1 建议支持单条件规则和多个条件全部满足的 AND 组合。嵌套 AND/OR 规则树留到后续版本，避免规则编辑器过早变成编程工具。

#### 预警状态

一次规则触发后生成独立预警事件，状态包括：

- 活跃：当前仍满足条件。
- 已读：用户已经查看，但条件仍存在。
- 已暂停：用户选择稍后提醒。
- 已解决：重新计算后不再满足条件。
- 已忽略：用户明确关闭本次事件，不关闭规则本身。

同一规则在冷却期内不得重复创建相同事件。记录被编辑、删除、恢复或统计周期结束后，系统必须重新计算状态。

#### 示例规则

| 规则名称 | 触发条件 | 周期 | 严重程度 | 作用 |
| --- | --- | --- | --- | --- |
| 现金安全线 | 现金储备 < ¥3,000 | 当前值 | 严重 | 防止可用现金跌破个人底线 |
| 跑道不足 | Runway < 2个月 | 最近3个完整月 | 严重 | 提醒现有现金只能维持较短时间 |
| 可变成本过高 | 可变成本 > ¥2,000 | 本月 | 关注 | 控制本月可调整成本 |
| 非必要成本偏高 | 非必要成本占比 > 25% | 本月 | 提示 | 发现可以削减的消费 |
| 财务依赖度偏高 | 财务依赖度 > 60% | 连续2个月 | 关注 | 观察收入来源独立性 |
| 收入来源集中 | 收入集中度 > 70% | 本年 | 关注 | 发现收入对单一来源的依赖 |
| 应付款临近 | 未来7天到期应付账款 > 现金储备的30% | 滚动7天 | 严重 | 提前识别短期现金压力 |
| 周成本异常 | 本周现金流出 > 最近4周平均值的130% | 自然周 | 关注 | 发现异常支出周 |
| 连续负现金流 | 净现金流 < 0 | 连续2个月 | 严重 | 识别持续性资金消耗 |
| 安全垫未达标 | 安全垫覆盖率 < 100% | 当前值 | 提示 | 跟踪个人安全垫目标 |

#### 预警展示结构

- 左侧导航增加“预警中心”，显示未读数量。
- 总览顶部只展示最高等级的少量活跃预警。
- 指标卡显示与该指标相关的预警标记。
- 日报、周报、月报和年报展示本周期触发、解决及持续中的预警。
- 预警详情必须显示：当前值、阈值、统计周期、触发时间、计算公式和关联记录。
- 用户可以从预警直接进入对应报告、指标或筛选后的记录。
- 没有足够数据时显示“暂无法评估”，不能把缺失值当作零触发预警。

#### 规则编辑体验

创建规则采用分步表单：

1. 选择要监控的指标。
2. 选择周期和比较方式。
3. 输入阈值或比较基准。
4. 设置连续周期、严重程度和重复频率。
5. 使用当前账本数据预览“如果现在启用，是否会触发”。
6. 保存并启用。

编辑器必须实时显示自然语言摘要，例如：“当本月可变成本大于 ¥2,000 时，发送关注级预警，每月最多提醒一次。”

#### 技术与安全边界

- 规则由 C# WarningEngine 在本机计算，React 只负责编辑和展示。
- 在启动应用、保存记录、编辑或删除记录、恢复备份及周期切换后重新评估。
- 不执行付款、转账、删除记录或其他自动财务操作。
- 预警不是投资、信贷或医疗建议，只说明用户设置的条件已经满足。
- Windows 通知默认隐藏金额，点击后只打开 LedgerX 对应预警。
- 规则和预警历史必须进入完整备份，并参与数据结构迁移。
- 自定义指标被删除前，必须提示有哪些预警规则依赖它。

### P2：暂不纳入 v2.1

- 自定义指标公式编辑器。
- 复杂嵌套 AND/OR 预警规则树。
- 预算与周期计划。
- 复杂资产折旧和固定资产处置。
- 多资金账户及账户间转账。
- 加密账本与应用锁。
- 云同步、手机端、登录账号。
- 自动读取银行、微信或支付宝。

这些功能都有价值，但与本轮“把本地数据管理做好”的目标不同。过早加入会增加恢复和迁移的数据模型风险。

## 4. 建议交互流程

### 4.1 导出备份

1. 用户点击“创建完整备份”。
2. 页面展示将包含的记录数、指标数和皮肤设置。
3. 用户选择目标文件。
4. 系统写入临时文件、校验可重新读取后，再替换为最终文件。
5. 页面显示成功时间、路径和校验状态。

### 4.2 从备份恢复

1. 用户选择备份文件。
2. 系统只读解析并校验，不立即覆盖数据。
3. 页面展示备份版本、创建时间、记录数、指标数和兼容性。
4. 用户确认后，系统先保存“恢复前快照”。
5. 使用临时文件完成原子替换并重新计算指标。
6. 显示恢复摘要；失败则自动保留原账本。

### 4.3 清空账本

1. 用户选择“清空账本”。
2. 页面说明会删除哪些内容、保留哪些设置。
3. 默认勾选“清空前创建备份”。
4. 用户输入“清空 LedgerX”。
5. 系统清空后显示恢复快照位置和“撤销清空”入口。

### 4.4 编辑记录

1. 在全部记录或指标明细中打开一条记录。
2. 修改字段时实时展示受影响指标。
3. 保存后重算指标并显示变化摘要。
4. 提供短时撤销；历史中记录更新时间。

## 5. 数据设计建议

建议为备份使用“信封 + 数据载荷”结构：

- formatVersion：备份文件格式版本。
- appVersion：创建备份的 LedgerX 版本。
- createdAt：备份创建时间，使用带时区的 ISO 8601。
- summary：记录数、自定义指标数和日期范围。
- checksum：对账本载荷计算 SHA-256，用于发现文件损坏。
- payload：完整 LedgerState。

LedgerState 建议新增：

- schemaVersion
- createdAt
- updatedAt
- lastBackupAt

FinanceRecord 建议新增：

- updatedAt
- deletedAt
- incomeSource
- isSelfGeneratedIncome

兼容原则：

- 新版本永远先识别旧格式，再迁移到内存模型。
- 迁移成功并验证后才能覆盖主数据文件。
- 未识别的未来版本必须拒绝恢复，不能猜测字段含义。
- 任何迁移都不能修改用户原始备份文件。

## 6. 非功能要求

- 所有账本写入继续采用临时文件加原子替换。
- 清空、恢复和结构升级前必须创建保护快照。
- 测试使用 LEDGERX_DATA_DIR 指向工作区内隔离目录。
- 日志不记录金额、备注、分类或完整文件内容。
- 在 1,000 条记录下，打开总览和保存记录的可感知等待不超过 300ms。
- 界面支持 125%、150% 和 200% Windows 缩放。
- 全部危险操作可仅用键盘完成，也能用 Escape 安全退出。

## 7. 测试清单

### 数据生命周期

- 空账本导出、恢复和清空。
- 有记录和自定义指标的完整备份。
- v2.0 原始 JSON 恢复。
- 校验和不一致、JSON 截断和未知未来版本。
- 恢复中断、磁盘空间不足和目标文件无权限。
- 清空后撤销，恢复后再次启动。

### 指标正确性

- 编辑收入后现金储备、净现金流和总资产同步变化。
- 编辑固定资产购置后现金减少、固定资产增加。
- 支付应付账款只减少现金和应付，不重复增加成本。
- 删除、恢复和清空后指标均从底层记录重算。
- 期间指标和时点指标在跨月记录下口径正确。

### 界面与宿主

- WebView2 首次启动和 Runtime 缺失提示。
- 100%、125%、150% 和 200% 缩放。
- 1360×860 默认窗口和 920×640 最小窗口。
- 恢复、清空和编辑流程无控制台错误。
- 图表在正常、空数据、数据不足、负值和超长分类名称下不溢出。
- 图表在暖铜、石墨、深海蓝和自定义 CSS 皮肤下保持可读。
- 图表下钻结果与原始记录合计一致，金额隐私模式无数值泄露。
- 阈值边界、连续周期、冷却时间和跨日/月边界触发正确。
- 编辑、删除、恢复记录后预警能重新评估并自动解决。
- 缺失数据、分母为零和样本不足不会触发误报。
- 单文件发布版实际启动验证，不只测试浏览器 Mock。

## 8. 建议开发顺序

1. 建立 schemaVersion、备份信封和兼容读取器。
2. 为 LedgerStore 增加验证、保护快照和原子恢复。
3. 完成恢复预览、清空确认和数据状态接口。
4. 完成记录编辑、软删除及撤销。
5. 加入统计周期、日报/周报/月报/年报、可视化图表和结构化收入来源。
6. 实现 WarningEngine、规则编辑器、预警中心和报告内预警。
7. 补齐 C# 单元测试、WebView 桥接测试和 Playwright 流程。
8. 进行跨电脑恢复、高 DPI 和最终单文件发布验收。

## 9. v2.1 完成定义

满足以下条件才认为 v2.1 可以发布：

- 用户无需进入资源管理器即可完成备份、恢复和清空。
- 恢复前能看到备份内容，且系统自动保护当前账本。
- 任意记录均可编辑或撤销删除，指标不会重复累计。
- v2.0 备份能够无损恢复。
- 所有期间指标明确显示统计周期。
- 日报、周报、月报和年报均可切换周期并下钻到原始记录。
- 趋势、结构和比较图表通过数据口径、响应式、主题及无障碍验收。
- 用户可以为任意可计算指标建立、预览、暂停和删除预警规则。
- 每次预警都能解释触发值、阈值、周期、公式和关联记录。
- 数据损坏不会被静默替换成空账本。
- 自动化测试和最终 EXE 验收全部通过。

一句话概括：v2.0 让 LedgerX 看起来像一款完整产品，v2.1 要让它在换电脑、录错账和准备重新做人时，也表现得像一款完整产品。
