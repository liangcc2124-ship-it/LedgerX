# LedgerX 个人财务管理软件需求文档

> 本文档已由 [LedgerX 产品需求文档 v2](./LedgerX-产品需求文档-v2.md) 取代，仅保留作为早期需求记录。

- 文档版本：v1.2
- 产品阶段：MVP 规划
- 产品名称：LedgerX
- 目标用户：仅软件所有者本人（单用户）
- 核心目标：清晰、持续、安全地统计个人资产、负债、收支与净资产变化

## 1. 产品概述

LedgerX 是一款仅供所有者本人使用的 Windows 电脑单机财务管理软件，不提供多用户、手机端或云端同步。全部数据由用户手动录入并仅保存在本机，不连接银行、券商、行情或其他在线服务。用户可以记录现金、银行卡、投资、房产等资产，以及信用卡、贷款等负债；系统统一计算总资产、总负债、净资产，并展示其随时间的变化。

产品首先解决三个问题：

1. 我现在拥有多少资产、承担多少负债？
2. 我的钱分布在哪里，近期为什么发生变化？
3. 我能否在不依赖网络和付费云服务的情况下，长期、安全地保存这些数据？

## 2. 产品原则

- **资产视角优先**：不只做日常记账，更关注完整资产负债表。
- **手动维护优先**：不依赖金融机构接口，录入和估值口径由用户掌控。
- **录入足够轻**：常用操作应在少量步骤内完成。
- **数据归用户所有**：支持完整导入、导出、备份与彻底删除。
- **完全离线**：不需要互联网连接，不建设云端服务，不产生云服务费用。
- **安全默认开启**：本地数据库和备份可加密，并支持应用锁。
- **结果可解释**：所有统计数字均可追溯到具体账户、交易或估值记录。

## 3. 用户与典型场景

### 3.1 目标用户

- 希望统一管理银行卡、现金、投资和贷款的个人用户。
- 希望观察净资产长期变化、但不想使用复杂会计软件的用户。
- 希望数据只保存在自己电脑中的用户。

### 3.2 核心场景

- 发工资后，在电脑上记录收入及账户余额变化。
- 消费后快速记录支出，并归入餐饮、交通等分类。
- 每月核对银行卡、信用卡和贷款余额。
- 在电脑端查看资产配置、月度收支和净资产趋势。
- 定期将加密备份复制到移动硬盘、U 盘或用户自行选择的目录。
- 更换电脑后，通过备份文件恢复全部数据。

## 4. 产品范围

### 4.1 MVP 必须包含

- 单用户账本初始化及应用锁。
- 资产账户与负债账户管理。
- 收入、支出、转账及余额调整。
- 资产负债表和净资产统计。
- 分类、标签、备注及搜索筛选。
- 月度收支和净资产趋势图。
- 可选指标库、自定义指标和财务分析工作台。
- 趋势、对比、结构、预算、预测及情景分析。
- CSV 导入与导出。
- 本机自动备份、手动备份及恢复。
- 基础安全和本地数据管理。

### 4.2 后续版本可包含

- 预算、账单提醒和订阅识别。
- OCR 小票识别、自然语言记账。
- 财务目标和更丰富的本地规则建议。
- 税务报表及更完整的多币种损益分析。

### 4.3 MVP 不包含

- 直接发起转账、支付或证券交易。
- 银行、信用卡或券商账户自动连接。
- 股票、基金、外汇或数字资产自动行情。
- 家庭共享及多人协作。
- 企业会计、发票、工资和税务申报。
- 面向公众的投资建议或收益承诺。

## 5. 功能需求

### 5.1 单用户账本与应用锁

用户可以：

- 首次启动时创建唯一的个人账本，不需要注册多个用户账号。
- 可选设置本机 PIN 或密码保护应用。
- 可设置一段时间无操作后自动锁定。
- 导出全部个人数据，以及永久删除本地数据。

### 5.2 资产项目与资金账户管理

账户类型至少包括：

- 现金
- 银行卡/储蓄账户
- 信用卡
- 投资账户
- 房产及其他实物资产
- 借款/贷款
- 其他资产或负债

每个账户包含：名称、类型、币种、初始余额、当前余额、图标/颜色、是否计入净资产、是否可立即使用、备注、创建时间及归档状态。

此处“账户”表示银行卡、现金、投资账户等财务项目，不是软件登录账号。用户可以新建、编辑、排序、归档这些项目；归档项目保留历史记录，但默认不出现在日常录入列表中。

### 5.3 交易记录

交易类型包括：

- 收入：增加指定账户余额。
- 支出：减少指定账户余额。
- 转账：一个账户减少、另一个账户增加，不计入收入或支出。
- 余额调整：用于对账，差额需保留明确的调整记录。

交易字段包括：金额、币种、账户、分类、日期时间、标签、商户/对象、备注、附件、创建来源和最后修改时间。

业务规则：

- 金额必须大于零，方向由交易类型决定。
- 转账必须同时记录来源账户和目标账户，并保持原子性。
- 删除交易采用软删除，以便恢复和审计。
- 编辑历史交易后，相关账户余额和统计结果必须自动重算。
- 支持重复交易的检测提示，但不自动删除。

### 5.4 分类与标签

- 提供常用收入、支出分类，可由用户增删改和排序。
- 分类支持一级与二级结构，例如“餐饮 / 外卖”。
- 已被交易使用的分类不可直接永久删除，可合并或归档。
- 标签允许一笔交易关联多个主题，例如“旅行”“可报销”。
- 收入分类可标记来源属性：父母支持、奖学金、兼职、实习、投资收益或其他。
- 支出分类可标记支出属性：固定或可变、必要或非必要；用户可以对单笔交易覆盖分类的默认属性。

### 5.5 资产估值

- 对现金、银行卡和信用卡，余额由交易累计计算。
- 对房产、车辆、收藏品等非交易型资产，用户可以手动记录估值及估值日期。
- 对投资账户，MVP 支持手动维护持仓总市值或通过余额调整更新。
- 所有资产价格、账户余额和汇率均由用户手动确认，系统不得将第三方估算值当作真实余额。
- 系统保留估值历史，不用新估值覆盖旧记录。

### 5.6 定期盘点

- 用户可以发起一次资产盘点，逐项确认各账户当前余额或估值。
- 系统显示上次确认时间，并标记长期未更新的账户。
- 用户输入实际余额后，系统展示与账面余额的差额，并由用户确认是否创建余额调整记录。
- 每次盘点形成带日期的净资产快照，用于长期趋势比较。
- 可设置仅在应用内显示的月度或季度盘点提醒。

### 5.7 仪表盘与报表

首页至少显示：

- 总资产
- 总负债
- 净资产
- 本月收入
- 本月支出
- 本月结余
- 现金储备与安全垫覆盖率
- Burn Rate 与 Runway
- 预算执行率与非必要支出
- 财务依赖度与自我造血能力
- 各资产类别占比
- 最近 6 至 12 个月净资产趋势
- 最近交易

计算口径：

- `净资产 = 计入统计的资产账户余额合计 - 负债账户余额合计`
- `期间结余 = 期间收入 - 期间支出`
- 账户间转账不影响期间结余和净资产，只改变资产分布。
- 报表必须显示统计时间范围、基准币种及数据更新时间。

用户可按日期、账户、分类、标签、币种和金额范围筛选，并下钻查看构成统计结果的原始记录。

### 5.8 预算与内置指标库

用户可以按月设置总支出预算，也可以为支出分类设置分类预算。系统提供以下指标作为可选模板，而不是强制启用的固定清单。用户可自由启用、停用、复制或调整模板；未启用的指标不出现在仪表盘和分析报告中。

系统基于手动录入的交易、账户余额、预算、预计收入和固定支出计算内置指标：

| 指标 | 定义与计算口径 |
| --- | --- |
| 现金流入 | 统计期内所有收入交易合计，包括父母生活费、奖学金、兼职等；转账不计入 |
| 现金流出 | 统计期内所有支出交易合计，包括吃饭、交通、娱乐、订阅等；转账不计入 |
| 净现金流 | `现金流入 - 现金流出` |
| 现金储备 | 当前所有标记为“可立即使用”的账户余额合计，如现金、银行卡、微信和支付宝余额 |
| 固定支出 | 统计期内标记为固定支出的交易合计，如会员、话费和住宿 |
| 可变支出 | 统计期内标记为可变支出的交易合计，如吃饭、娱乐和购物 |
| 非必要支出 | 统计期内标记为非必要的支出交易合计，并显示其占总支出的比例 |
| 预算执行率 | `实际计入预算的支出 / 对应预算 × 100%`；未设置预算时显示“未设置”，不能显示为 0% |
| 资金缺口 | `max(0, 下一笔预计收入前的预计必要支出 - 可动用现金)` |
| 安全垫 | 用户为意外情况设定的目标金额，并显示当前现金储备对目标的覆盖率 |
| 资金链 | 比较下一笔预计收入日期前的可动用现金与预计必要支出，显示“充足”“偏紧”或“存在缺口” |
| 流动性 | 同时显示可立即使用的金额，以及 `流动资产 / 总资产` 的比例 |
| 现金消耗率 / Burn Rate | 默认取最近 3 个完整月的平均每月支出；可切换为当月支出或自定义区间 |
| Runway（现金跑道） | `可动用现金 / 月均现金消耗率`，单位为月；缺少有效支出数据时显示“数据不足” |
| 收入集中度 | `最大单一收入来源金额 / 总现金流入 × 100%`；显示贡献最大的收入来源 |
| 财务依赖度 | `父母支持类收入 / 总现金流入 × 100%` |
| 自我造血能力 | `兼职、实习等自主收入 / 总现金流出 × 100%`，表示自主收入对生活支出的覆盖程度 |
| 开源节流 | 分别展示自主收入变化和可控支出变化，不强行合并成一个分数 |
| 降本增效 | 展示非必要支出金额、占比及环比变化，帮助识别可削减项目 |
| 资产配置 | `某类资产当前价值 / 总资产 × 100%`，按现金、投资、实物资产等分类展示 |

补充规则：

- 用户可录入下一笔预计收入的日期、金额和来源，以及未来固定支出的日期与金额。
- “可立即使用”“固定/可变”“必要/非必要”“自主收入”等属性必须允许用户自行修改。
- 指标卡必须显示统计周期和计算说明，并可下钻到组成该指标的交易或资产项目。
- 分母为零或数据不足时显示“暂无数据”或“无需计算”，不得显示误导性的百分比或无穷大。
- 预计数据与已发生数据在界面上使用不同样式，不能混合成实际现金流。
- 月度对比至少支持本月、上月和最近 3 个月平均值。

### 5.9 自定义指标引擎

用户可以创建不限于内置列表的自定义指标。每个指标包含：

- 名称、简称、说明和所属分组。
- 指标类型：金额、百分比、比率、时长、数量或文本状态。
- 计算公式，以及参与计算的数据范围。
- 默认统计周期：本月、上月、近 3 个月、近 12 个月、自然年或自定义区间。
- 筛选条件：交易类型、账户、资产类型、分类、标签、收入来源、固定/可变、必要/非必要等。
- 聚合方式：求和、平均值、最大值、最小值、数量、期初值、期末值或变化率。
- 显示格式：小数位、货币单位、百分比、正负数颜色及图表类型。
- 可选目标值、警戒值和状态区间。
- 是否启用、是否固定到首页、排序位置及适用报表。

公式编辑器要求：

- 支持引用基础字段，例如收入合计、支出合计、账户余额、预算、预计现金流和资产估值。
- 支持引用其他已保存指标，例如 `现金储备 / Burn Rate`；系统必须检测并禁止循环依赖。
- 支持加、减、乘、除、括号、`min`、`max`、`abs`、条件判断和安全除法。
- 提供可视化公式构建器，用户不需要编程即可选择数据、筛选条件和运算方式；高级用户可切换到公式文本模式。
- 保存前使用当前数据预览结果，并显示公式错误、单位不匹配、除零或数据缺失问题。
- 修改指标时保留版本历史；用户可恢复旧版本，已有历史报表应记录当时使用的指标版本。
- 删除被其他指标引用的指标时必须提示依赖关系，禁止直接破坏下游公式。
- 支持将自定义指标导出和导入为独立配置文件，但配置文件不得包含财务数据。

### 5.10 财务分析

财务分析模块全部在本机运行，根据已启用的指标和用户手动录入的数据生成结果，不调用云端 AI 或外部分析服务。

分析能力包括：

- **概览分析**：按月、季度和年度汇总资产、负债、现金流、预算及已启用指标。
- **趋势分析**：显示金额、比例或状态随时间的变化，并支持移动平均。
- **环比与同比**：比较本期与上期、去年同期的绝对变化和变化率。
- **结构分析**：分析支出分类、收入来源和资产配置的组成与变化。
- **贡献度分析**：指出哪些收入来源、支出分类或资产项目对总变化贡献最大。
- **预算分析**：识别超预算、接近预算和剩余预算，区分固定与可控支出。
- **现金流预测**：根据用户录入的预计收入、固定支出和当前现金储备，预测未来资金余额与可能的缺口日期。
- **情景分析**：用户可临时调整收入、支出、预算或安全垫，查看“如果这样变化”的结果，但不修改真实账本。
- **异常提示**：根据用户设定的阈值或历史区间提示大额支出、支出突增、收入下降、流动性不足等情况。
- **分析结论**：使用规则生成简明文字说明，必须同时展示依据、统计周期和相关数据，不得输出投资建议或无法追溯的结论。

用户可以保存分析视图，配置其中的指标、筛选条件、时间范围、对比基准、图表和排序。系统提供“月度复盘”模板，但用户可以删除模板或从空白视图开始。

分析设计应区分三类指标：

- **核心结果指标**：例如净现金流、现金储备和 Runway，用来判断总体财务状态。
- **驱动指标**：例如自主收入、固定支出和非必要支出，用来解释结果为何变化。
- **风险护栏指标**：例如资金缺口、安全垫覆盖率和收入集中度，用来提示风险。

系统不强制用户采用任何一套指标组合；此分组只用于组织、筛选和分析解释。

### 5.11 多币种

- 每个账户拥有固定币种，用户设置一个基准币种。
- 不同币种之间转账允许分别记录转出和转入金额，并保存实际汇率。
- 汇率由用户手动维护，系统保留每次使用的汇率记录。
- 汇总报表使用选定日期的汇率折算，并明确显示汇率来源和时间。

### 5.12 搜索、导入与导出

- 支持按关键词搜索交易备注、商户、账户、分类和标签。
- 支持从标准 CSV 模板批量导入账户与交易。
- 导入前提供字段映射、格式校验、重复检测和预览。
- 支持将全部或筛选后的数据导出为 CSV；完整备份可导出为 JSON 或加密备份包。
- 导入失败必须指出具体行号和原因，不得静默丢弃数据。

### 5.13 备份与恢复

- 应定期在用户选择的本机目录创建自动备份，并设置保留数量或周期。
- 用户可主动创建加密备份文件，并将其自行复制到 U 盘、移动硬盘或其他位置。
- 备份文件不得依赖 LedgerX 云服务，换电脑安装 LedgerX 后也能导入恢复。
- 用户可在恢复前查看备份时间、应用版本和数据范围。
- 恢复操作应二次确认，优先创建恢复前快照。
- 应定期验证备份可恢复性，而不只是确认备份文件存在。

## 6. 单机存储方案

### 6.1 产品决策

LedgerX 第一版只提供 Windows 电脑端，不建设手机端、服务器、用户注册或云数据库。软件安装后即可离线使用，因此没有云服务的持续费用。

数据只保存在本机。软件卸载、硬盘损坏或电脑丢失都可能造成数据丢失，因此本地备份与可迁移的备份文件属于 MVP 必备能力。

### 6.2 本地存储要求

- 业务数据使用嵌入式 SQLite 数据库保存在用户电脑中。
- 数据库路径明确可查，但用户不能通过界面误删正在使用的数据库。
- 所有写操作使用事务；异常退出或断电后不得留下半笔转账。
- 软件启动时检查数据库完整性，发现异常时提示从备份恢复。
- 数据库结构升级必须先创建备份，并支持失败后回滚。
- 附件保存在专用本地目录，备份时与数据库一起打包。

### 6.3 推荐技术架构

- 桌面应用：Tauri + React，兼顾较小安装包和现代界面；Electron 也可作为备选。
- 本地数据库：SQLite。
- 数据访问层：通过事务维护账户余额、转账和估值记录。
- 图表：使用本地前端图表库，不调用在线图表服务。
- 打包：生成 Windows 安装包，核心功能不依赖网络。
- 更新：默认由用户手动下载安装包；自动更新如后续加入，应允许关闭。

### 6.4 未来扩展边界

当前版本明确不实现同步。如果未来重新需要手机端，可以新增云同步或由用户自建同步服务，但应作为独立版本规划，不能让单机功能依赖它。

## 7. 数据模型概要

核心实体包括：

| 实体 | 关键字段 | 说明 |
| --- | --- | --- |
| Ledger | id, base_currency, settings | 唯一的本地账本及偏好 |
| Account | id, type, currency, balance | 资产或负债项目 |
| Transaction | id, account_id, type, amount, occurred_at | 收入、支出或调整 |
| Transfer | id, source_transaction_id, target_transaction_id | 连接转账两端 |
| Category | id, parent_id, type | 收支分类 |
| Tag | id, name | 自定义标签 |
| Valuation | id, account_id, value, valued_at | 非交易型资产估值 |
| ExchangeRate | base, quote, rate, effective_at | 汇率记录 |
| Budget | period, category_id, amount | 月度总预算或分类预算 |
| PlannedCashFlow | type, amount, expected_at, category_id | 预计收入与未来固定支出 |
| MetricDefinition | id, name, formula, unit, filters, enabled | 内置或自定义指标定义 |
| MetricVersion | metric_id, version, definition, created_at | 指标公式与配置版本历史 |
| Dashboard | id, name, period, layout | 用户保存的分析视图 |
| DashboardWidget | dashboard_id, metric_id, chart_type, position | 分析视图中的指标与布局 |
| AnalysisRule | id, condition, severity, message_template | 本地异常提示和文字结论规则 |
| Scenario | id, name, assumptions | 不影响真实账本的情景分析参数 |
| Attachment | id, transaction_id, storage_key | 票据或凭证 |
| ChangeLog | entity_id, operation, changed_at | 本地操作历史与审计记录 |

所有业务实体都应包含 `created_at`、`updated_at` 和可选的 `deleted_at`，用于审计、软删除和恢复。

## 8. 非功能需求

### 8.1 安全与隐私

- 核心功能不得向互联网发送财务数据、使用统计或附件。
- 自定义指标只能使用受控公式语法，不允许执行任意 JavaScript、SQL、系统命令或访问本地文件。
- 应用锁密码使用专用密码哈希算法保存，不得明文或可逆加密存储。
- 本地数据库和备份支持加密，密钥不写入日志或备份明文元数据。
- 敏感日志不得记录应用锁密码、完整账户号码或原始附件内容。
- 展示层默认只显示账户别名及尾号，不存储非必要的完整银行卡信息。
- 删除全部数据时必须明确列出将删除的本地数据库、附件和备份范围。

### 8.2 性能与可靠性

- 常用页面应在普通个人电脑上快速完成首屏展示。
- 单用户十万条交易记录时，搜索、筛选和月度汇总仍应保持可用。
- 常用指标计算结果应按数据版本缓存；交易或指标变化后只使相关缓存失效。
- 关键写操作必须具备事务性，转账不得出现部分成功。
- 数据库异常应提供清晰错误提示、日志位置和备份恢复入口。
- 导入操作中断后可安全重试。

### 8.3 可用性与无障碍

- 桌面窗口支持常见分辨率和缩放比例，核心功能支持键盘操作。
- 金额、日期、币种格式遵循用户地区设置。
- 高风险操作提供清晰确认与撤销入口。
- 图表不能仅靠颜色传达含义，并提供数据表或文字摘要。

## 10. MVP 验收标准

- 用户能创建至少一个资产账户和一个负债账户，并得到正确的净资产结果。
- 收入、支出、转账、余额调整均正确影响账户余额及报表。
- 转账不计入收入或支出，编辑或删除后两端状态仍一致。
- 软件断网时所有核心功能均能正常使用，且不会尝试上传财务数据。
- 用户可按时间、账户和分类筛选交易，并从汇总数字下钻到原始记录。
- 现金流入、现金流出、净现金流和预算执行率符合文档计算口径，转账不会重复计入。
- 用户设置下一笔预计收入和未来必要支出后，系统能够正确显示资金缺口与资金链状态。
- Runway、财务依赖度、自我造血能力和资产配置均能下钻到对应的原始数据。
- 未设置预算、分母为零或历史不足时，指标显示明确的缺省状态而不是错误数值。
- 用户可以只启用所需内置指标，首页和报告不显示被停用的指标。
- 用户可以通过可视化构建器创建自定义指标，并在保存前预览计算结果。
- 自定义指标可以引用其他指标；循环依赖、除零和单位不匹配会被识别并阻止保存。
- 用户修改指标后可查看并恢复历史版本，删除指标不会破坏引用它的公式。
- 趋势、环比、结构、贡献度和预算分析均能下钻到原始记录。
- 情景分析不会修改真实交易、账户余额或实际报表。
- 所有自动生成的分析结论都能显示计算依据、统计周期和关联数据。
- CSV 导入可预览并报告错误，导出数据可被再次导入。
- 用户可以创建加密备份，并在另一台 Windows 电脑上完整恢复。
- 删除账户前有明确影响提示，删除的交易在保留期内可恢复。

## 11. 迭代计划建议

### 阶段一：单机核心功能

- 完成账户、交易、分类、仪表盘和 SQLite 本地数据存储。
- 验证数据模型、计算口径和基础交互。

### 阶段二：指标与财务分析

- 完成可选指标库、自定义公式构建器、指标依赖校验和版本管理。
- 完成趋势、对比、结构、贡献度、预算、预测和情景分析。

### 阶段三：数据安全与迁移

- 加入应用锁、本机自动备份、加密备份包、恢复和数据库迁移。
- 验证异常退出、断电、数据库升级和跨电脑恢复场景。

### 阶段四：可用产品

- 完成导入导出、安全加固、性能优化和 Windows 安装包发布流程。
- 完成不同分辨率、缩放比例和 Windows 版本的兼容性测试。

### 阶段五：增强能力

- 预算、盘点提醒、自然语言录入和基于用户自有数据的智能分析。

## 12. 主要风险与决策

| 风险或决策 | 影响 | 建议 |
| --- | --- | --- |
| 电脑或硬盘损坏 | 唯一本地副本可能永久丢失 | 提醒用户定期将加密备份复制到外部存储 |
| 手动录入出现遗漏或滞后 | 净资产不能反映最新状态 | 加入盘点流程、上次更新时间和应用内提醒 |
| 忽略对账和估值历史 | 净资产数据逐渐失真 | MVP 即加入余额调整和估值快照 |
| 自定义指标公式错误 | 可能形成错误判断 | 保存前预览、单位校验、缺失值提示和版本回滚 |
| 指标过多造成信息负担 | 仪表盘失去重点 | 默认只启用少量核心指标，由用户选择其余指标 |
| 分析结论看似正确但不可解释 | 用户可能误信结果 | 所有结论必须展示公式、周期、来源记录和触发规则 |
| 忘记应用锁或备份密码 | 加密数据可能无法恢复 | 创建时明确提示并允许用户妥善保存恢复信息 |
| 自动备份和主数据库在同一硬盘 | 硬盘故障时两者同时丢失 | 支持自定义备份目录并提示使用外部磁盘 |

## 13. 待确认的产品决策

进入界面和开发设计前，需要进一步确认：

- 是否只支持 Windows，还是未来也需要 macOS 版本。
- 是否需要记录股票、基金等具体持仓与手动收益计算，而不只是投资账户总市值。
- 是否需要多币种及手动汇率换算。
- 是否默认加密本地数据库，及忘记密码后的处理方式。
- 自动备份频率、保留数量和默认备份目录。
- 第一版公式编辑器需要支持哪些函数，以及是否允许用户编写公式文本。
- 默认启用哪些核心指标，首页最多展示多少张指标卡。
