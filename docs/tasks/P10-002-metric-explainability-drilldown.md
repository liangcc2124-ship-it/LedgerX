# P10-002：指标解释、来源下钻与分析门禁

- 状态：BLOCKED（等待 P10-001）
- 类型：可解释分析、跨模块查询与性能验收
- 依赖：指标模板、P8 记录检索和 P5 Dashboard 合同稳定
- 影响：Dashboard/metrics query DTO、记录筛选链接、Vue 卡片/详情、20k 性能测试

## 用户结果

用户看到任一指标时可以回答三个问题：这个数代表什么、使用了哪个期间和口径、由哪些记录/账户事实组成。下钻后的记录列表必须与指标计算使用同一服务端过滤语义。

## 服务端合同

1. Dashboard 卡片增加有界 `explanation`：期间、数据状态、公式/系统口径摘要、依赖指标 ID、可用的 drilldown descriptor；不返回原始全量记录。
2. drilldown descriptor 使用稳定、签名或服务端可验证的查询参数集合，映射到 P8-002 记录 query；Vue 不从展示文本逆向拼筛选。
3. 支持记录事实的指标进入收支记录页并显示规范筛选；账户余额类进入账户明细/截至日期视图；纯派生指标先展示依赖树，再由用户选择可下钻依赖。
4. EMPTY、NOT_COMPUTABLE、DEPENDENCY_UNAVAILABLE 和循环/坏引用分别显示原因与修复动作，不能统一显示 0 或“暂无数据”。
5. breakdown 补齐 P5-004 遗留规则：维度、排序、Top N、Other、精度和空值均在 Java 定义；响应大小有上限。

## UI

- 卡片保留名称、值和状态；“查看构成”进入详情，不把全部解释塞进小卡。
- 详情展示口径、当前/上一期间、趋势、依赖和构成；金额隐私开启时解释和下钻仍不能泄露数值。
- 从详情进入记录列表后可返回原指标，并保留期间/粒度；profile 切换使旧 drilldown 失效并返回总览。
- 技术字段和枚举通过 presentation map 转为中文，但诊断日志保留稳定代码。

## 验收与性能

- 系统收入、总支出、可用现金和四个模板指标都有黄金解释与下钻结果。
- 指标值、breakdown 总和和下钻记录聚合一致；编辑/删除/恢复记录后 dataRevision 使三者同时更新。
- 20,000 条记录、50 个指标、100 节点公式图下 Dashboard P95≤750ms；详情/下钻 P95≤500ms；无 N+1 查询。
- 未来期间、空账本、零分母、归档引用、profile 切换和隐藏金额均有真实浏览器→Java HTTP→SQLite 证据。
- P5-008 与 P6-008 的剩余分析闭环在本任务最终验收中关闭，随后才能把指标/总览标为正式可用。

## 禁止事项

不得在前端重新计算或筛选来“解释”服务端结果；不得返回整本账目作为 evidence；不得持久化易失的派生值，除非性能测量证明必要并另立缓存 ADR。
