# P8-002：记录检索、组合筛选与完整汇总

- 状态：待排期（记录检索增强，不阻塞当前使用）
- 类型：查询能力、API 扩展与可用性
- 依赖：本机运行基线可用；仅在实际检索需要时排期
- 影响：ledger-records 规格、记录 query/repository/HTTP、Vue RecordsPage、索引与性能测试

## 用户结果

在 20,000 条记录下，用户能按日期、类型、分类、账户、金额和备注关键词组合查找记录，并看到基于完整筛选结果而非当前已加载页面的收入、支出和净额。

## 查询合同

1. 复用现有 cursor 分页和筛选字段；新增前先核对当前 API，已有字段不得另造同义参数。
2. 日期采用 `[occurredFrom, occurredToExclusive)`；类型最多三种；分类/账户使用稳定 ID；金额为精确十进制字符串；关键词 trim 后 1–200 字符。
3. 响应继续返回 `items/page/meta`，并增加服务端计算的 `summary`：匹配记录数、收入、固定支出、弹性支出、总支出、净额、币种和规范查询范围。summary 针对完整结果集，不受 page limit 影响。
4. cursor 必须绑定 profile、全部规范筛选、排序键和 dataRevision；任何条件变化清空旧 items/cursor 并取消过期请求。
5. 默认稳定排序为 `occurredOn DESC, createdAt DESC, id DESC`。首版不提供任意列排序，避免破坏 cursor 契约。
6. 关键词搜索仅覆盖 note 和明确批准的展示字段；使用转义参数化 SQL。先用现有索引和有界 LIKE，只有 20k 测量不达标时才评估 FTS，并另记 ADR。

## 前端行为

- 提供月份快捷选择、自定义日期、类型、分类、账户、金额范围和关键词；“清除筛选”恢复默认当前月。
- URL hash 只保存页面，不保存敏感查询；页面挂载期间保持筛选，profile 切换后全部重置。
- 筛选变更使用短延迟和 AbortController；慢旧响应不能覆盖新条件。
- 记录按月份显示分组标题；“加载更多”保持当前筛选和 summary，不重复项目。
- 空结果显示当前筛选摘要和清除按钮，不误报“还没有记录”。

## 验收与性能

- 正常、回收站分别覆盖单条件、组合条件、空结果、第 51 条、条件切换竞态和过期 cursor。
- 20,000 条合成记录下常用查询 P95≤500ms；响应不返回未请求的全量行。
- summary 与独立 SQL 黄金结果精确一致，删除/恢复/编辑后 dataRevision 和汇总同步变化。
- 输入包含 `%`、`_`、长中文、空格、emoji 和不存在引用时结果安全、稳定。
- Java/SQLite/HTTP/Vue 与真实本机浏览器链路各有对应证据。

## 禁止事项

不得在浏览器对已加载 50 条做“全量汇总”；不得使用 offset 分页；不得把金额转为浮点；不得为了搜索引入远程索引、缓存服务或新数据库。
