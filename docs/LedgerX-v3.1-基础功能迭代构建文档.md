## 1. 版本结论

v3.1 的主题是：**把 v3.0 已经铺开的基础能力真正接通，并让普通用户能看懂、能操作、能验证。**

本次属于中等规模的行为修复迭代。假设是单机、单进程、单个 Windows 用户、每个用户空间最多数万条记录和数百个指标，不存在服务器流量、多人并发或合规报税需求。继续使用现有本地单体架构；不拆服务、不引入消息队列、不建设脚本插件系统。

### 1.1 必须达成的用户结果

1. 新记录使用标准分类库，并可在当前用户空间内创建全局可复用的自定义分类。
2. 长表单滚动到边界时，背景页面不再跟着滚动。
3. 日、周、月、年订阅自动计算服务结束日，用户无需重复填写。
4. 财务总览卡片可用鼠标拖动和缩放，内容随卡片尺寸重排而不被裁切。
5. “归集指标”只在确有可归集指标时出现，且永远是可选项。
6. 固定资产展示真实累计折旧和账面净值，并说明、推荐折旧方法。
7. 新增指标去掉重复的“常用”分组，公式模板和自定义入口更清楚。
8. 固定资产只保留一个数据源和一个用户入口，不再在设置中放置业务数据页面。
9. 公式可引用用户创建的指标和当前公式上下文中的时间变量，构建器对新手可用。
10. “数值记录”改成有明确用途的“指标数据”，并从普通财务记录流程中降级为按需入口。
11. 所有按钮、筛选器和标题在缩放与窄屏下完整显示。
12. 日期显示本地化文字，不再出现 `yyyy/mm/日` 之类占位符。

### 1.2 非目标

- 不做云同步、在线账号、银行/微信/支付宝自动导入。
- 不做库存、商品 SKU、发票、税务申报或企业总账。
- 不允许任意文本脚本、Excel 公式字符串、网络函数或文件函数。
- 不为固定资产新增一套与记录脱离的账本。
- 不在 v3.1 增加预算、OCR、AI 自动分类或复杂审批流。
- 不新增常驻“资产中心”侧栏菜单；先通过“固定资产”指标卡进入资产明细。

## 2. 现状核查与根因

以下结论来自所附界面截图和仓库当前实现，不只是视觉推测。

| 问题 | 当前根因 | v3.1 修复方向 |
| --- | --- | --- |
| 分类下拉出现用户过去录入的“流量卡、校园网、AI”等 | 迁移代码把旧记录文本直接提升为分类，初始系统分类又只有十个平铺项 | 引入稳定的两级标准分类库；历史文本保留为用户分类但不冒充系统分类 |
| 分类下拉过长并遮住表单 | 使用原生平铺 `select`，无场景过滤、搜索和分组 | 使用稳定的两级分类、场景过滤和自定义分类；保留原生选择器的键盘能力 |
| 弹窗到底后背景继续滚动 | `.modal` 自身滚动，但打开时未锁定页面，未阻断 overscroll chaining | 锁定背景滚动，弹窗正文独立滚动，阻断滚动链 |
| 月订阅仍要求服务结束日 | C# 已有 `InferServiceEnd`，React 表单和保存命令没有调用 | 前端即时计算，后端保存时再次推导和校验 |
| 卡片布局只能点键盘式按钮 | `Overview.tsx` 只有上/下/加宽/减宽按钮，没有指针拖放 | 使用成熟的响应式网格拖拽与缩放组件，复用现有 `x/y/w/h` 数据 |
| 归集指标为空却保存时报“请选择自定义指标” | 表单写入 `metricTargetIds`，后端旧校验却检查 `customMetricId`；快照又遗漏 `acceptsDirectRecordAssignment` | 统一指标模型和字段；无可归集指标时隐藏整块；普通记录不强制指标 |
| 新增指标的“全部”和“常用”重复 | 后端给所有模板都返回 `group="常用"`，前端再额外生成“全部” | 删除“常用”，给模板返回真实业务分组 |
| 自定义公式看似保存但没有正确关联 | `saveMetricDefinition` 忽略 `formulaId`，同时存在 `CustomMetricDefinition` 与 `MetricDefinition` 两套来源 | 以 `MetricDefinition` 为唯一权威模型，旧模型仅用于迁移兼容 |
| 公式面板可点但经常无法形成合法表达式 | 前端展示 `IF`，后端不支持；函数需要逗号/常量但面板未提供；所有作用域共用同一数据源列表 | 后端提供按作用域生成的公式目录；前端根据期待的下一构件启用按钮 |
| 公式“试算”不是真实试算 | 前端只拼一段说明文字，后端预览固定返回 0 | 使用当前账本、当前统计期间和真实公式引擎返回值、口径与错误 |
| 折旧方法选了也只看到直线法结果 | `PreviewDepreciation` 无视所选方法，只计算 `(原值-残值)/月数` | 预览与正式值统一调用 `AllocationEngine.BuildDepreciationSchedule` |
| 固定资产卡片没有折旧后价值 | `MetricEngine` 仍把固定资产购置金额直接求和，快照也不返回折旧结果 | 固定资产指标改为活动资产账面净值之和，原值和累计折旧作为拆分项 |
| 设置中的固定资产像另一套数据 | 设置页同时承担偏好和业务对象管理，且只显示原值/残值 | 从设置移除；固定资产指标详情直接展示同一 `FixedAssets` 集合 |
| 日期占位和筛选区难看、被压缩 | 直接依赖 WebView 的 `input[type=date]` 展示；筛选网格对内容最小宽度约束不正确 | 新增统一 `DateField`，ISO 存储、本地化显示；筛选器按宽度换行 |
| 父级分类可能显示 GUID | `RecordModal` 直接插值 `category.parentId` | 所有界面通过 ID 查父级名称，绝不向用户显示内部 ID |

## 3. 产品与数据原则

### 3.1 分类的“全局”范围

本构建基线暂定为：**分类在当前用户空间内全局有效**。同一空间的新增/编辑记录、筛选、报表、指标和设置使用同一分类库；不同用户空间仍相互隔离。这与现有“每个空间拥有独立账本、分类和指标”的承诺一致。

这是唯一需要产品方最终确认的数据边界。如果确认要跨所有用户空间共享，应另做 profile index 级别的迁移，不能在实现时悄悄改变隔离规则。该待确认项不阻塞按当前空间全局方案开工。

### 3.2 分类、指标和指标数据必须分清

- 分类回答：**这笔财务事实是什么？** 例如“软件与云服务”。
- 归集指标回答：**是否把这笔记录额外计入某个允许手工归集的自定义指标？** 例如“创作工具成本”。
- 指标数据回答：**这个值不是钱，而是指标计算要用的数量。** 例如 12 小时、320 公里、85 kWh。

一条普通财务记录必须有分类，可没有归集指标；指标数据可以先独立保存，也可以选择一个允许直接录入的指标，不强制影响现金。

### 3.3 固定资产单一事实源

- 购置记录负责现金流和取得事实。
- `FixedAsset` 负责原值、残值、启用日、寿命、折旧方法和处置状态。
- 两者通过 `AcquisitionRecordId` / `FixedAssetId` 双向关联。
- 累计折旧和账面净值是按指定日期计算的派生值，不再信任可能过期的缓存值。
- 编辑、软删除、恢复或永久删除购置记录时，必须对关联资产进行一致性检查和明确提示。

## 4. P0 功能规格

### 4.1 标准分类库与自定义分类

#### 4.1.1 分类结构

参考 Google Product Taxonomy 和 Shopify Standard Product Taxonomy 的做法：系统分类使用稳定 ID 和层级路径，用户另有自定义类型；LedgerX 不复制完整电商目录，只选取个人财务需要的两层分类。

默认大类和二级分类如下：

| 大类 | 二级分类 |
| --- | --- |
| 收入 | 工资薪酬、奖金、兼职与自由职业、经营收入、投资收益、退款报销、家庭支持、礼金与赠与、其他收入 |
| 食品与餐饮 | 食材与生鲜、外出餐饮、零食饮料、外卖 |
| 服饰与个护 | 服装、鞋靴箱包、美妆护肤、个人护理 |
| 居住与家庭 | 房租与房贷、物业、水电燃气、家具家居、家电、维修维护、日用品 |
| 交通与车辆 | 公共交通、打车、燃油充电、停车路桥、车辆维修、车辆购置 |
| 数码与办公 | 电脑、手机与平板、影音摄影、配件耗材、办公设备 |
| 通信与数字服务 | 手机通信、网络宽带、软件与云服务、AI 服务、影音会员、游戏与内容会员 |
| 医疗与健康 | 药品、门诊住院、体检、健身运动、健康设备 |
| 教育与成长 | 书籍、课程培训、考试认证、学费 |
| 休闲与社交 | 旅行住宿、娱乐演出、兴趣爱好、礼物人情、宠物 |
| 保险与金融 | 保险、利息与手续费、税费、还款、其他金融支出 |
| 专业与其他服务 | 咨询与专业服务、维修服务、快递物流、其他服务 |
| 固定资产 | 房屋及装修、电脑及电子设备、手机及平板、家具及家电、车辆、机器及工具、影音摄影设备、其他固定资产 |
| 应付款 | 信用卡、消费分期、贷款、待付账单、其他应付款 |
| 其他 | 未分类、其他支出、其他非资金事项 |

分类选择器按记录场景过滤：收入只优先显示收入类；周期成本优先显示通信与数字服务、居住、保险等服务类；固定资产优先显示固定资产类。用户可展开“全部分类”。

#### 4.1.2 自定义与迁移

- 选择器底部提供“＋ 新建自定义分类”。保存后立即写入当前用户空间的分类库，并在所有相关页面可用。
- 自定义分类可指定父级大类，可改名、合并和归档。
- 系统分类允许停用，不允许永久删除；稳定 ID 不因改显示名称而变化。
- 旧账本中由自由文本生成的分类全部保留，标记为“历史自定义分类”，不会删除或改写历史记录。
- 历史自定义分类在新记录选择器的“自定义”分组中显示，不再排在系统推荐之前。
- 不做复杂迁移向导；设置中的分类管理提供“合并到标准分类”操作即可。
- 后端保存时验证 `CategoryId` 属于当前用户空间且未归档；`Category` 文本只作为兼容快照，不再是权威字段。

#### 4.1.3 交互

- 使用按场景过滤的分组式选择器，不再让无关分类挤满表单；选择器仍保留原生键盘导航。
- 选择结果显示大类与二级分类路径；自定义分类在所有场景可复用。
- 行内显示 `大类 / 二级分类`，不显示 GUID。
- 默认焦点和键盘导航可用；Esc 先关闭选择器，再关闭表单。

### 4.2 弹窗滚动、焦点与操作区

- 打开任一模态弹窗时锁定页面滚动，并保存背景滚动位置；关闭后恢复原位置。
- 弹窗结构拆成固定标题区、唯一可滚动正文区、固定操作区。
- 正文使用 `overscroll-behavior: contain`，滚到顶/底继续滚轮时背景不得移动。
- 背景设为 inert；Tab/Shift+Tab 不得离开弹窗；Esc 关闭；关闭后焦点回到打开弹窗的按钮。
- 小高度窗口中正文滚动，保存/取消按钮始终可见。
- 下拉菜单、日期选择器和提示不得超出可视区域。

### 4.3 周期服务结束日自动计算

#### 4.3.1 规则

| 计费周期 | 服务结束日（不含当日） |
| --- | --- |
| 按日 | 开始日 + 1 天 |
| 按周 | 开始日 + 7 天 |
| 按月 | 开始日 + 1 个自然月 |
| 按年 | 开始日 + 1 个自然年 |
| 一次性 | 不显示服务结束日；按付款/发生日确认 |
| 自定义 | 用户填写结束日，必须晚于开始日 |

- 普通日/周/月/年周期下，结束日为只读计算结果，不要求手填。
- 修改服务开始或计费周期时立即重算。
- 月末按日历规则处理：2026-01-31 按月得到 2026-02-28；闰年 2028-01-31 得到 2028-02-29。
- 前端只负责即时展示；后端用同一规则重新推导，不能信任客户端提交的派生日期。
- 界面显示“2026年10月10日（不含当日）”，并提供一句说明：“9月10日开始的月订阅覆盖到10月9日结束”。

#### 4.3.2 分摊预览

保存前展示当前选择对现金与成本的不同影响，例如：

> 2026年9月10日支付 ¥30；现金当日减少 ¥30。服务期 9月10日至10月9日，成本按服务天数分摊。

预览必须由后端分摊引擎计算，不在 React 中复制金额公式。

### 4.4 总览卡片鼠标拖拽与自适应

#### 4.4.1 依赖选择

本次采用现有 `DashboardLayoutItem(x,y,w,h,min/max)` 加原生 Pointer Events 实现最小桌面网格，不新增拖拽依赖。这样符合本迭代“先完成基础功能”的范围；碰撞自动重排、三套独立断点布局和复杂拖拽无障碍增强留作后续版本。

#### 4.4.2 桌面交互

- “编辑布局”开启后，每张卡片显示清晰的“移动”和“缩放”指针操作按钮，并保留键盘微调按钮。
- 鼠标按住拖动把手移动卡片；按住缩放把手改变宽高。
- 卡片不能拖出总览区域，不能缩到低于内容可用的最小尺寸。
- 拖动/缩放停止时保存一次，过程中不持续写磁盘。
- “完成布局”退出编辑；“恢复默认布局”需二次确认并立即重排。
- 现有键盘操作不作为主界面按钮继续占位，但必须保留可访问的移动/调整尺寸方式，可放入“更多布局操作”菜单。

#### 4.4.3 断点与内容自适应

- `>= 1024px`：12 列，可拖动、可缩放，保存 desktop 布局。
- `768–1023px`：6 列，可排序，尺寸受更严格最小值限制，保存 tablet 布局。
- `< 768px`：单列自然流，不开启自由缩放；可按拖动把手排序，保存 mobile 顺序。
- 指标卡按容器宽度分为 compact / standard / wide 三种内容密度；金额字号使用有上下界的 `clamp()`，不使用 transform 整体缩放。
- 金额和标题不使用省略号；必要时换行，次要解释可在 compact 模式减少，但完整内容必须能从详情进入。
- 图表在容器变化后重新测量；最近记录卡根据高度展示 3–8 行，不裁切表头和操作入口。

### 4.5 归集指标与“指标数据”

#### 4.5.1 归集指标

- 标题固定为“归集到自定义指标（可选）”。
- 说明固定为：“需要同一笔记录额外计入你创建的指标时再选；不选不影响保存。”
- 只列出 `AcceptsDirectRecordAssignment=true` 且未归档的 `MetricDefinition`。
- 没有可归集指标时整块隐藏，不展示空白大框，也不触发任何必填校验。
- 公式计算型指标默认不允许直接归集；“直接录入型”指标创建时明确开启。
- 后端以 `MetricTargetIds` 为唯一多选归集字段；`CustomMetricId` 只用于 schema 3 迁移，迁移后不再写入。

#### 4.5.2 数值记录改名与入口

“数值记录”改名为“指标数据”，在新增记录中保留为一个清晰说明用途的轻量场景；没有自定义指标时不要求归集，也不会影响现金。

当用户拥有直接录入型指标时，表单显示“归集到指标（可选）”；没有可归集指标时显示一行解释，仍允许保存独立的指标数据。指标数据使用不影响资金的结算方式，并可在公式构建器中引用记录聚合和时间变量。

独立的指标数据快捷入口留作后续迭代；本版先确保新增记录流程可保存、可解释且不误扣现金。

适用例子：工时、里程、用电量、产量、体重。普通用户若只记账，可以永远不接触这套入口。

### 4.6 固定资产、折旧和菜单逻辑

#### 4.6.1 页面入口

- 从“设置”移除“固定资产”页签。设置只保留数据与偏好、用户空间、分类、资金账户。
- 点击总览或指标中心的“固定资产”卡片，进入固定资产指标详情。
- 固定资产详情顶部显示三项：资产原值、累计折旧、账面净值。
- 下方列出每项资产：名称、分类、启用日期、方法、原值、累计折旧、本期折旧、账面净值、剩余寿命、状态。
- “新增固定资产”仍调用新增记录表单的固定资产场景，保证现金与资产同时建立。
- 编辑资产参数、处置资产都在同一详情页完成，不在设置中另建副本。

#### 4.6.2 折旧方法说明与推荐

| 方法 | 简单说明 | 推荐场景 | 计算要求 |
| --- | --- | --- | --- |
| 直线法（默认） | 每期折旧基本相同，最容易理解 | 家具、家电、普通办公设备、长期均匀使用的资产 | 原值、残值、使用寿命 |
| 工作量法 | 按实际使用量折旧，用得多折得多 | 车辆里程、机器工时、按次数使用的设备 | 预计总工作量、本期工作量 |
| 双倍余额递减法 | 前期折旧较多，后期逐渐减少 | 更新快、前期价值下降快的电脑、手机、电子设备 | 原值、残值、使用寿命 |
| 年数总和法 | 按剩余使用年限加速折旧，但变化比双倍余额递减法平缓 | 前期效用较高且逐年下降的设备 | 原值、残值、使用寿命 |
| 自定义 | 使用受限结构化公式 | 上述方法确实不适用且用户理解公式时 | 合法公式与完整变量 |

推荐只是预选，不强制。选择资产分类后显示“推荐：直线法/双倍余额递减法”等理由，用户可以更改。

#### 4.6.3 计算口径

- 可折旧金额 = 原值 − 残值。
- 直线法月折旧 = 可折旧金额 ÷ 使用寿命月数。
- 工作量法本期折旧 = 可折旧金额 × 本期工作量 ÷ 预计总工作量。
- 双倍余额递减法按年折旧率 `2 ÷ 使用寿命年数` 计算，再按月分摊；任何时点账面净值不得低于残值。
- 年数总和法按标准年度权重计算，再按月分摊。不能继续使用当前“把月份直接做年数总和”的近似算法。
- 折旧从启用日开始，不早于取得日；处置日后停止。
- 所有方法的最后一期处理舍入差额，确保 `累计折旧 <= 原值 - 残值`。
- 固定资产指标值 = 所有未处置资产在统计期末的账面净值之和，不再等于购置原值之和。
- 总资产 = 可用资产账户余额 + 固定资产账面净值 + 其他已支持资产；净资产再减负债。

示例验收：原值 ¥12,000、残值 ¥0、寿命 12 个月、直线法，完整 3 个月后累计折旧必须为 ¥3,000，账面净值为 ¥9,000。

### 4.7 新增指标与公式构建器

#### 4.7.1 模板库

删除“常用”分组。模板只出现一次，可用以下业务分组筛选：

- 全部
- 现金与流动性
- 收入与支出
- 订阅与成本
- 资产与负债
- 风险与效率

指标创建只保留两条清晰路径：

1. 选择模板并预览公式、所需数据和当前试算值；
2. 从空白创建自定义指标。

不再额外提供会与模板列表重复的“常用”页。

#### 4.7.2 主流基础公式模板

| 指标 | 默认公式 | 数据不足时 |
| --- | --- | --- |
| 净现金流 | 现金流入 − 现金流出 | 显示 0，并说明期间无现金记录 |
| 储蓄率 | 净现金流 ÷ 现金流入 × 100% | 收入为 0 时显示“暂无法计算” |
| 固定成本率 | 已确认固定成本 ÷ 现金流入 × 100% | 收入为 0 时显示“暂无法计算” |
| 平均月支出 | 最近 N 个完整月现金流出 ÷ N | 完整月份不足时显示“样本不足” |
| 资金可支撑月数 | 可用现金 ÷ 平均月支出 | 支出为 0 时显示“暂无消耗” |
| 负债率 | 总负债 ÷ 总资产 × 100% | 总资产为 0 时显示“暂无法计算” |
| 净资产 | 总资产 − 总负债 | 正常显示负数 |
| 固定资产净值 | 资产原值 − 累计折旧 − 累计减值 | 无资产时显示 0 |
| 本期订阅成本 | 服务期与统计期重叠天数 ÷ 服务总天数 × 记录金额 | 无重叠时显示 0 |

这些模板是个人管理口径，不声称符合特定国家税法。模板创建后允许改名、改筛选和复制，但内置系统指标不应被改成互相矛盾的口径。

#### 4.7.3 数据源目录

数据源不能继续由 React 写死为十个字符串。后端返回带稳定 ID、显示名、类型、作用域和说明的目录。

**指标公式可用：**

- 系统指标：现金流入、现金流出、已确认固定/可变成本、账户余额、负债、资产原值、累计折旧、资产净值等；
- 用户指标：当前用户空间内所有未归档且不会形成循环引用的 `MetricDefinition`；
- 记录聚合：按记录类型、分类、资金账户和统计期间筛选后的金额合计/数量/平均值；
- 时间：统计期间天数、完整月数、期间开始距今天数、期间结束距今天数。

**分摊公式可用：**

- 记录金额、服务开始、服务结束、服务总天数、与统计期间重叠天数、已过天数、剩余天数、已过月数。

**折旧公式可用：**

- 原值、残值、可折旧金额、启用日期、截至计算日已使用天数/月数、寿命月数、当前账面价值、预计总工作量、本期工作量。

“购买以来的时间”必须来自具体记录或资产上下文。没有绑定记录/资产的普通指标不能凭空使用这个变量；界面要说明为什么不可选，避免得到没有定义的结果。

#### 4.7.4 构建器交互

- 数据源卡片按“系统指标、我的指标、记录聚合、时间变量”分组，可搜索。
- `×` 表示乘法；删除操作改为构件右上角独立的圆形关闭按钮，并使用关闭图标，不能与乘号混淆。
- 运算显示“＋ 加、− 减、× 乘、÷ 除”。
- 函数显示“Σ 求和、x̄ 平均、四舍五入、最小值、最大值、绝对值、限制区间”。英文函数名只在帮助文字中显示。
- 在后端实现并测试前，不展示 `IF`。如果保留条件计算，必须正式增加比较节点、真假分支、类型校验和测试，不能只放一个按钮。
- 提供数字常量输入；需要多参数时由界面生成参数槽位，不要求小白手动插入逗号。
- 根据语法状态禁用不合法的下一步，例如公式开头不能点乘号，运算符后不能再点除号。
- 实时显示可读公式，例如“（净现金流 ÷ 现金流入）× 100%”。
- “试算”调用后端真实数据，返回当前值、统计期间、数据状态、所引用来源和错误位置。
- 保存前检查空公式、除零、类型不匹配、归档引用和循环引用；失败时保留用户已经搭好的公式。

#### 4.7.5 权威模型收敛

- `MetricDefinition` 成为模板指标、自定义公式指标和直接录入型指标的唯一权威定义。
- `CustomMetricDefinition` 在 schema 4 迁移时转换为 `MetricDefinition`；读取旧备份时保留兼容，之后不再双写。
- `MetricDefinition` 必须序列化 `FormulaId`、`TemplateId`、`PeriodBehavior`、`AcceptsDirectRecordAssignment`、`IsEnabled` 和 `IsArchived`。
- 前端保存自定义指标时必须把已保存的 `formulaId` 真正写入定义。

### 4.8 日期与响应式基础控件

#### 4.8.1 日期

新增统一 `DateField` 组件：

- 数据与 bridge 继续使用 ISO `YYYY-MM-DD`，避免迁移和时区歧义。
- 用户看到 `2026年9月11日`；日期范围显示 `2026年9月1日 – 9月30日`。
- 空值显示“选择日期”，不显示格式占位符。
- 点击整块控件或日历图标打开 WebView 原生日期选择器；支持键盘和屏幕阅读器。
- 开始/结束日期要有持久标签、最小/最大约束和就地错误。
- 所有记录表单、指标详情筛选、报告和预警日期统一替换。

#### 4.8.2 按钮、标题和筛选器

- 按钮按内容决定宽度，短标签保持一行；空间不足时操作组换行或在窄屏变为整行，不裁切文字。
- 不使用 transform 缩小整个按钮；字号仅在可读范围内用 `clamp()` 微调。
- 触控目标建议 44×44 CSS px；图标按钮必须有可访问名称。
- Flex/Grid 中承载文字的子项设置 `min-width: 0`，长中文、英文、数字和路径可换行。
- 指标详情的标题和筛选区在窄宽度改为上下结构，不能再出现截图中的标题逐字断行、日期框内容被截断。
- 320、375、768、1024、1440 px 和 200% 缩放下不得出现页面级横向滚动、按钮文字缺失或无法触达的保存按钮。

## 5. 数据和接口变更

### 5.1 schema 4 迁移

迁移前创建保护快照。迁移必须幂等，可重复加载同一份 schema 3 数据而不生成重复分类、指标或资产。

1. 写入新的稳定系统分类树；ID 由固定常量提供，不按显示名称临时生成。
2. 保留现有分类和记录关联；非系统旧分类标记为历史自定义分类。
3. 将每个 `CustomMetricDefinition` 转为 `MetricDefinition`；若已有同 ID 定义则合并，不重复创建。
4. 把旧 `CustomMetricId` 合并进 `MetricTargetIds`，去重后保留；以后只写 `MetricTargetIds`。
5. 把可识别的旧公式字符串标签映射到稳定 source ID；无法识别的公式标记为“需修复”，不静默改成 0。
6. 保留现有 dashboard `x/y/w/h`；首次打开时为 tablet/mobile 派生安全默认布局。
7. 固定资产与购置记录按现有 ID 补齐关联；冲突进入 `MigrationIssues`，不猜测覆盖。

### 5.2 建议 DTO

最小新增/补齐以下可序列化结构：

```text
CategoryDefinition
  id, name, parentId, applicableRecordTypes, isSystem,
  isArchived, isLegacyCustom, sortOrder,
  defaultRecognitionMethod, recommendedDepreciationMethod

MetricDefinition
  id, name, description, displayFormat, precision,
  formulaId, templateId, periodBehavior,
  acceptsDirectRecordAssignment, isEnabled, isArchived

FormulaSourceDescriptor
  id, label, group, valueType, scopes, description,
  referencedMetricId?, requiresContext?

FixedAssetView
  id, acquisitionRecordId, name, categoryId, inServiceDate,
  cost, salvageValue, method, usefulLifeMonths, status,
  periodDepreciation, accumulatedDepreciation, bookValue,
  remainingLifeMonths
```

后端负责生成 `FormulaSourceDescriptor` 和 `FixedAssetView`，前端不维护平行口径。

### 5.3 时间与测试时钟

涉及“今天”、服务期和累计折旧的服务应通过可替换的时钟或显式 `asOf` 参数计算，测试中不得依赖运行当天。所有日期按本地自然日处理，桥接层只传日期，不传带 UTC 偏移的午夜时间戳。

## 7. 验收标准

### 7.1 分类

- Given 新用户空间，When 打开收入、日常支出、周期成本和固定资产表单，Then 各自先显示对应标准分类，而不是历史自由文本。
- Given 已有“AI”历史分类，When 升级，Then 历史记录分类不丢失，“AI”出现在自定义分组，系统同时提供“通信与数字服务 / AI 服务”。
- Given 在表单内新建“生产力工具”，When 保存，Then 当前用户空间内设置、筛选和其他记录表单立即可见；其他用户空间不受影响。
- 所有位置显示分类名称路径，不显示 GUID。

### 7.2 弹窗与日期

- Given 背景页面已滚动，When 打开长表单并把弹窗滚到最底后继续滚轮，Then 背景 `scrollTop` 不变化。
- When 用 Tab 遍历弹窗，Then 焦点不进入背景；Esc 关闭后焦点回到原按钮。
- Given 空日期，Then 显示“选择日期”，不显示 `yyyy/mm/日`。
- Given 任何保存/取消按钮，When 320px 宽、低高度窗口或 200% 缩放，Then 按钮完整可见且可点击。

### 7.3 订阅

- Given 2026-09-10 开始、按月，Then 自动结束日为 2026-10-10。
- Given 2026-01-31 开始、按月，Then 自动结束日为 2026-02-28。
- Given 2028-01-31 开始、按月，Then 自动结束日为 2028-02-29。
- Given 自定义周期，Then 用户必须填写晚于开始日的结束日。
- 前端预览、保存结果和报告确认成本使用同一后端算法。

### 7.4 指标与公式

- Given 没有直接归集型指标，When 保存任意普通财务记录，Then 不显示归集区且保存成功。
- Given 一个公式型指标，Then 它不出现在归集列表；Given 一个直接录入型指标，Then 它可选但不必选。
- Given 用户创建指标 A，When 创建指标 B，Then B 的数据源中能按名称选择 A，并按稳定 ID 保存。
- Given A 引用 B 且 B 已引用 A，Then 保存前拒绝并明确指出循环链。
- Given 除数为 0，Then 显示“暂无法计算”和修复建议，不伪装成 0。
- 前端不展示后端不支持的函数；每个展示函数都能通过界面完整构造并由后端成功解析。
- “试算”返回真实当前值和期间，修改记录后再次试算结果同步变化。

### 7.5 固定资产

- Given 原值 ¥12,000、残值 0、寿命 12 月、直线法、完整使用 3 月，Then 累计折旧 ¥3,000、账面净值 ¥9,000。
- Given 双倍余额递减或工作量法，When 预览，Then 结果与正式保存后的详情一致，不再都显示直线法金额。
- 任一方法下账面净值不低于残值，累计折旧不超过可折旧金额。
- 固定资产卡片展示账面净值；详情同时展示原值、累计折旧和净值，并可下钻到资产及购置记录。
- 设置中不再出现固定资产页签。

### 7.6 总览布局与响应式

- Given 桌面宽度，When 用鼠标拖动并缩放卡片后重启应用，Then 布局保持。
- Given 卡片缩到允许的最小尺寸，Then 标题、金额和主要操作不裁切、不显示省略号。
- Given 320、375、768、1024、1440px，Then 页面无意外横向滚动，按钮文字不缺失，标题不逐字断行。
- Given 200% 缩放，Then 所有功能仍可达，表单保存区不被遮挡。

| 风险 | 控制方式 |

| 分类升级误改历史记录 | 只新增标准库并保留历史自定义分类；合并必须由用户主动执行 |
| 两套指标模型继续分叉 | 先做 schema 4 收敛，再改界面；禁止继续双写 |
| 拖拽交互复杂度 | 先用原生 Pointer Events 完成移动/缩放和边界约束；碰撞重排、更多断点留作后续 |
| 折旧口径被误认为税务结论 | 界面和文档标明个人管理口径；推荐可改，不做税法承诺 |
| 时间变量缺少上下文 | 数据源描述声明作用域；只有绑定记录/资产时才开放“自购买以来”变量 |
| 复杂公式把小白挡在门外 | 模板优先；自定义公式是次级入口；不在 v3.1 扩展成完整编程语言 |

## 10. 参考依据

- [Shopify Standard Product Taxonomy](https://help.shopify.com/en/manual/products/details/product-category)：标准分类和自定义产品类型分开、分类使用层级路径和稳定标准值。
- [Google Product Category](https://support.google.com/merchants/answer/6324436)：标准分类按从大类到具体子类的层级组织，并强调选择最具体的匹配分类。

- [MDN: input type=date](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/input/date)：底层值保持 `YYYY-MM-DD`，显示格式由本地化界面处理。
- [W3C Modal Dialog Pattern](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/)：模态背景 inert、焦点留在弹窗内、Esc 关闭和大内容初始焦点原则。
- [IAS 16 Property, Plant and Equipment](https://www.ifrs.org/content/dam/ifrs/publications/pdf-standards/english/2022/issued/part-a/ias-16-property-plant-and-equipment.pdf?bypass=onStep)：折旧方法应反映资产经济利益的预期消耗方式；常见方法包括直线法、余额递减法和工作量法。
- [IRS Publication 946](https://www.irs.gov/publications/p946)：直线法和余额递减法的计算解释，仅作为方法学参考，不作为 LedgerX 的税务规则。
