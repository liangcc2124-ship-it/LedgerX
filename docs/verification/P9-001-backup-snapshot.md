## 真实闭环

使用隔离临时数据根启动打包后的 Java 服务。浏览器新建并编辑 1 条记录后，从设置页创建备份；界面显示文件、账目摘要和完整性状态。浏览器再次调用深度校验并下载包，确认 UUID 文件名及下载内容非空。随后重启 Java 服务，确认备份仍在列表中并能重新校验；主账本继续保留原记录，后续回收站恢复及第二次重启后金额仍为 13.50 CNY。

E2E 脚本在退出时清理专用临时目录，没有复制或修改默认 `%LOCALAPPDATA%\LedgerX` 数据。生成的设置页截图保存在系统临时目录，未加入仓库；同时检查了桌面宽屏呈现，窄屏无横向溢出由浏览器回归覆盖。

## 结果与限制

- SQLite 在线备份期间业务写入仍可继续；自动化测试覆盖 64 MiB SQLite 数据与真实写入重叠、`integrity_check`/`foreign_key_check`、同一幂等键并发只发布一个包、坏 hash、截断 ZIP、未知格式、跨 profile 不可见及源业务 revision 不因创建备份而改变。
- 不新增数据库表或迁移；备份写入本机数据目录 `Backups/<profile-id>/`，并使用同目录 staging、重开复验和同卷原子发布。
- 文件**未加密**。同盘的本地副本不能防止磁盘损坏；应把下载文件另存到可信的独立位置。
- 本轮没有故障注入磁盘写满、Windows 权限拒绝或进程强杀；实现失败时采用不发布半成品的路径，但这些环境故障尚无自动化演练证据。
- 本功能只证明备份包可验证和下载，不证明当前版本能够从包恢复。恢复流程需单独定义数据替换、备份保护和失败回滚。
