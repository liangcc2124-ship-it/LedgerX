# LedgerX Java 11 基础账本与财务总览需求基线

- 状态：已接受，可进入模块规格与任务拆分
- 日期：2026-09-23
- 阶段：架构基线修订；不代表目标实现已经完成
- 现状基线：仓库 v3.1 的 WPF/WebView2 + React/TypeScript + 本地 JSON 实现
- 基础版范围裁决：[ADR-010](./decisions/ADR-010-basic-ledger-scope.md)
- 指标与总览范围裁决：[ADR-011](./decisions/ADR-011-enable-metrics-dashboard.md)

## 1. 目标

将 LedgerX 重构为一个在 Windows 本机运行、由系统浏览器访问的网页应用。当前交付目标不是完整复制 v3.1，而是在稳定基础记账闭环上增加可信、可解释的财务总览：

- 后端使用 Java 11，负责基础收支规则、事务、SQLite 和诊断；
- 前端使用 HTML、CSS、JavaScript、Vue 3 和 Vite，负责展示与交互；
- 前后端能够独立启动、构建、测试，通过本机版本化 REST API 协作；
- Java 独立启动本机服务，同源提供 Vue 静态资源和 API，用户在系统浏览器访问 `127.0.0.1`；
- 最终只有一个本机服务入口和一个本地用户操作的网页产品，不演变成微服务或云系统；具体裁决见 [ADR-014](./decisions/ADR-014-local-browser-only.md)。

基础账本以分类、账户、收入/固定支出/弹性支出、余额、记录编辑和回收站为事实来源；本轮在其上增加系统指标、自定义计算指标、安全公式、财务总览、日/周/月/年视图、桌面卡片布局和当前 profile 的手动一致性备份。固定资产、分摊、手工非现金指标值、报表/预警、旧 JSON 导入和应用内恢复仍延后。当前 WPF/React 版本继续作为历史行为参考，不要求逐项等价。

## 2. 规模评估与假设

### 2.1 分类

**产品规模：小型；本轮功能规模与跨层风险：中等。**

运行时由 Java 服务管理账本，系统浏览器只承载 Vue 界面。基础收支正确性、数据持久化和 HTTP 契约需要测试，但没有多人权限、金融合规、独立扩缩容或分布式一致性需求。

### 2.2 维度假设

| 维度 | 当前与可信近期假设 | 设计影响 |
| --- | --- | --- |
| 范围 | 基础记账闭环，加指标/公式/四级总览；其余高级财务能力延后 | 只基于已有可信事实计算，不以 v3.1 全功能等价阻塞迭代 |
| 寿命 | 继续维护 3–5 年 | API、schema、备份均显式版本化 |
| 用户/流量 | 单设备、单操作者、可有多个本地用户空间；无公网流量 | 一个 Java 写者足够，不做分布式系统 |
| 数据量 | 单人日常账本；实际规模以本人使用为准 | SQLite + 已有索引 + 有界分页；出现卡顿时再测量 |
| 团队 | 1–3 名维护者，前后端可分别开发 | 同仓库清晰目录和契约测试，不拆多个服务仓库 |
| 部署 | Windows 10/11 x64，个人单机自用，不面向他人发布 | Java 本机服务与 Vue 静态资源组成一个本机运行单元，不设计安装器或分享包 |
| 安全 | 单机、单用户；不提出金融合规、角色、加密或审计需求 | loopback 限制、同源浏览器会话、CSRF 防护和 Host/Origin 校验 |
| 集成 | 无第三方在线 API；本轮只增加后端生成与下载的本机备份，不需要文件导入、通知或任意路径访问 | 指标、布局和备份仍走本机 REST，不新增桌面桥接能力 |
| 变化频率 | 指标、公式和卡片会按个人使用反馈迭代 | Vue 与 Java 独立开发，日期与计算规则只在后端实现，公式定义版本化 |

## 3. 已确认决定与安全假设

1. Java 11 是后端源码和生产运行时硬约束，编译使用 `--release 11`。
2. 目标前端固定为 Vue 3 + Vite + HTML/CSS/JavaScript；首期不使用 TypeScript、SSR 或 Nuxt。
3. 不再使用 Electron；Java 自主提供本机网页与 API，不引入桌面壳。
4. 前后端以 `/api/v1` REST/JSON 契约独立开发；开发和生产都由同源入口访问 API。
5. SQLite 替代活动账本 JSON；一次只允许一个 Java 后端写入。
6. 只直接导入 v3.1 `schemaVersion=4` 和备份 `formatVersion=2`；更旧版本先由现有程序升级。
7. 首期仅 CNY、最多两位小数；不提供多币种。
8. 不加入应用锁、数据库加密或加密备份；必须如实说明依赖 Windows 账户和磁盘权限。
9. 备份/恢复以单个用户空间为单位。
10. 界面按功能、内容、核心交互和可访问性等价，不要求与旧 WebView2 像素级一致。
11. 先不考虑 PDF 报表导出，不保留占位按钮或空接口。
12. 2026-09-15 的文档阶段限制属于历史记录；当前以最新用户任务和 P7–P10 任务规格为准。
13. 产品仅供用户本人在本机使用；不做对外发布、安装器、在线更新或代码签名。若将来使用范围改变，再单独补充分发和维护要求。
14. 基础版只开放 `INCOME`、`FIXED_COST`、`VARIABLE_COST` 三类记录；每条记录必须选择活动分类、活动账户和结算日，统一按 `PAID_FROM_ACCOUNT` 影响账户余额。
15. 基础记录不接收或返回资产、分摊、指标归集、应付款、批量永久清理字段或 endpoint。相关数据库表可保留为空，不能因此阻塞基础记录实现。
16. 不为本项目引入金融安全或金融合规需求：不做角色权限、审批、操作审计、数据库/备份加密、反欺诈、监管报送或交易级风控。本机浏览器会话仍须防范跨站请求、DNS rebinding 和非 loopback 访问；原 Electron Bearer 注入仅属迁移前实现。
17. P9-001 支持在 LedgerX 运行时为当前 profile 创建 format 3 一致性备份；恢复仍必须在应用完全退出后整体替换事先保存的完整数据目录。应用内恢复、备份上传/导入和旧 JSON 导入属于后续可选能力。
18. 按 ADR-011 启用系统指标、自定义计算指标、公式校验/预览、财务总览和布局；基础记录 DTO 仍不增加指标归集、资产或分摊字段。
19. 总览只提供日、周、月、年四种自然期间粒度，周一为一周起点，默认当前月。收入/支出按发生日，现金流/余额按结算日，所有期间由 Java 统一计算。
20. 自定义公式可引用指标、分类收入/支出、账户余额和时间变量；分类与账户引用保存稳定 ID。分类引用包含该分类及当前后代，重新归类会重算历史结果。
21. 公式编辑器中文优先，英文函数名可作为兼容别名；持久化和 API 使用规范 AST，不保存或执行任意 JavaScript/SQL。
22. 总览卡片只在显式编辑模式中拖动和缩放，采用 12 列桌面网格；四种时间粒度共享每个用户空间的一份布局。本轮不适配手机端。
23. 指标、上一期比较和趋势由后端按请求计算，不持久化计算结果缓存。常规性能关注真实数据和实际体验；大规模压测仅在用户数据增长或出现卡顿时安排。
24. 每个账本必须由用户明确初始化起始日和默认账户期初余额。业务自然日固定使用 `Asia/Shanghai` 与注入 Clock；V004 安装日只保留为旧迁移兼容事实。V006 把结构有效的历史账本安全自动完成、模糊状态设为 REVIEW_REQUIRED、结构损坏则回滚，不重写历史金额或记录。

## 5. 范围

### 5.1 包含

- Java 11 模块化单体后端及独立 Maven 构建。
- Vue 3/JavaScript 前端及独立 npm 构建、测试和浏览器开发模式。
- Java 本机服务启动、浏览器打开/提示、同源静态资源与 API、服务退出语义。
- 本机 `127.0.0.1` REST API、浏览器会话与 CSRF、版本、错误、分页、幂等和并发契约。
- 用户空间、设置、分类和账户管理。
- 收入、固定支出、弹性支出的新增、查询、编辑、移入回收站和恢复，以及账户余额重算。
- 基于现有记录与账户的系统指标、自定义计算指标、中文优先公式编辑、校验、预览和不可变版本。
- 财务总览的日、周、月、年视图、上一期比较、趋势分桶、空数据/不可计算状态。
- 桌面卡片的显式编辑、拖动、缩放、保存、取消和恢复默认布局；布局按用户空间隔离。
- SQLite 事务、约束、索引、schema history 和健康检查。
- 共享 JSON fixtures、Java API 集成测试、Vue 测试和真实浏览器→HTTP→Java→SQLite E2E。
- 当前 profile 的运行中手动一致性备份：创建、列表、深校验和下载；以及退出服务后的完整数据目录恢复说明。

### 5.2 非目标

- 云同步、远程服务器、移动端、网页登录、多人协作或远程访问本机 API。
- 微服务、消息队列、事件总线、通用插件框架、ORM、依赖注入容器或服务发现。
- 银行/支付/券商/行情/OCR/AI 在线集成。
- SSR、Nuxt、前端直接 Node.js/SQLite 访问、Electron 及其他桌面壳。
- 预算、转账、应付款、固定资产、成本分摊、手工非现金指标值、记录到指标的归集、报表、预警、CSV/旧 JSON 导入、多币种、附件、税务等高级能力。
- 任意 JavaScript/SQL 公式。
- PDF 报表导出。
- 应用内恢复、上传/导入、自动备份/保留删除、保护快照、备份加密、主题导入/导出。
- 金融合规、角色权限、审批、操作审计、数据库加密、加密备份、反欺诈或监管报送。
- Java 与旧 C# 同时写入同一活动数据，或 Java 数据反向同步旧 JSON。
- 手机和平板专用布局、触摸拖拽、云端同步布局，以及日/周/月/年各自独立布局。

## 6. 核心用户流程

### 6.1 启动

1. 用户启动 Java 本机服务；它解析 `%LocalAppData%\LedgerX` 为数据根，仅隔离测试可覆盖。
2. Java 只绑定 `127.0.0.1` 的临时端口并完成数据库初始化；监听成功不代表业务已就绪。
3. Java 打开系统浏览器或明确输出本机 URL；浏览器从同一 Java origin 加载 Vue 和 `/api/v1`。
4. 浏览器取得同源短期会话与 CSRF 凭据后查询 `system/status`；`STARTING` 禁用业务操作，`READY` 进入活动空间，恢复或失败状态显示可操作页面。
5. 关闭浏览器标签不停止服务；用户有明确的服务退出方式，退出后数据库句柄释放。
6. 若 active profile 的 `setupState` 为 PENDING/REVIEW_REQUIRED，先进入账本初始化/审查流程；普通记账、设置和总览能力由 Java 服务端阻断，提交初始化前不开放业务导航。

### 6.2 前后端独立开发

1. 前端开发者单独启动 Vue/Vite；Vite 将 `/api` 代理到 Java 开发实例。
2. 后端开发者单独启动 Java，以 API fixtures/集成测试验证契约，不依赖前端 UI。
3. 双方只依赖 `docs/api.md`、具体 API 文档和共享 fixtures；不得通过导入对方内部类或数据库表耦合。

### 6.3 记录与重载

1. 用户填写记录并提交；Vue 发送精确金额、业务日期、引用 ID、幂等键和并发版本。
2. Java 校验分类、账户、日期和金额，在一个 SQLite 事务内保存一条 `finance_record`，同时更新数据版本和幂等结果；基础版不写资产、分摊或指标表。
3. 返回创建结果、实体版本和数据版本；Vue 更新记录列表和账户余额。
4. 关闭并重启后，记录和余额保持一致。

### 6.4 编辑、删除和恢复

- 编辑使用乐观并发版本；冲突时不覆盖较新数据。
- 普通删除进入回收站并可恢复；基础版不提供永久清理或批量删除。
- 失败时事务回滚并给出稳定错误码，不出现半保存。

### 6.5 手工备份与恢复

- 用户可在服务运行时为请求开始时的当前 profile 创建一致性、可校验、可下载的 format 3 备份；普通记账可继续，切换 profile 不得改变在途备份归属。
- 备份明确未加密，只通过同源浏览器会话 API 按 opaque ID 操作，不接收或返回本机绝对路径。
- 本轮不提供应用内恢复。需要恢复时仍须停止服务、先保留当前完整数据目录，再按人工说明整体替换；不得只复制运行中的 `ledger.db`。

### 6.6 财务总览与四级视图

1. 用户进入财务总览，默认看到当前月及默认启用的八个系统指标。
2. 用户切换日、周、月、年或移动到相邻期间；Vue 只提交粒度和锚点日期，Java 返回规范期间、余额截止日、上一期间、指标值和趋势序列。
3. 小卡完整显示名称、值、单位和状态；中卡增加上期比较；大卡增加与当前粒度匹配的趋势或构成。完全未来、空数据和不可计算都有明确状态，不伪造为成功的零。
4. 收支记录新增、编辑、删除、恢复或切换 profile 后，下一次总览读取必须反映最新 `dataRevision`，前端不得继续展示其他 profile 或旧版本的结果。

### 6.7 自定义指标与布局

1. 用户新建指标，选择名称、说明、显示格式、小数位，并在结构化公式编辑器中用中文函数和稳定引用构造公式。
2. 保存前可针对当前视图预览；语法、引用、类型、复杂度、循环或除零风险失败时给出可定位错误，且不写数据库。
3. 保存成功新增不可变公式版本并原子切换指标当前版本；历史期间按当前版本重新计算，旧版本仍可审查。
4. 用户进入布局编辑模式，通过鼠标移动和缩放卡片；保存后重启仍保持，取消不写入，恢复默认只重置当前 profile 的总览布局。

## 7. 可验证验收标准

### 7.1 架构与独立开发

- `frontend/` 能单独执行安装、开发、构建和前端测试，不编译 Java；旧 `web/` 保留为迁移对照直到验收。
- Java 后端能单独执行编译、单元和 API 集成测试，不启动浏览器。
- 系统浏览器通过同源 REST 连接 Java；Vue 不导入 Java 类、不读取数据库、不调用 Node.js 通用 API。
- 生产包不存在 JavaFX/WebView bridge 运行依赖；旧实现仅作为迁移和对照基线。

### 7.2 跨层验收矩阵

| 用户操作 | 前端反馈 | 跨层字段 | 业务结果 | 持久化结果 | 边界 |
| --- | --- | --- | --- | --- | --- |
| 启动应用 | 加载态后进入主页或恢复页 | request ID、API/应用/schema 版本 | 仅一个后端会话可写 | 打开活动 profile | 后端超时、端口占用、坏库、窗口重载 |
| 初始化新账本/审查旧账本 | 日期/账户表单，完成后开放导航；损坏数据进入恢复提示 | setupState、ledgerStartOn、openingBalance、确认开户日、幂等键 | Java 校验所有日期并按用户确认调整；错误不改写历史记录 | V006 状态、默认账户、settings/data revision、operation 同事务提交 | V005 空/有数据/TRASHED/归档、重复/并发、迁移回滚 |
| 新建/编辑记录 | 成功后列表和账户余额更新；错误就地显示 | amount/currency、occurredOn、recordType、categoryId、accountId、settlementOn、note、revision、幂等键 | 收入增加资产账户余额、支出减少；负债账户方向相反 | record、dataRevision、operation 同事务提交 | 空值、零/负金额、归档引用、重复提交、冲突 |
| 删除/恢复 | 回收站状态明确，余额随最终状态变化 | ID、If-Match、幂等键 | 删除取消余额影响，恢复重新计入 | `deleted_at` 与 revision 持久化 | 重复删除/恢复、归档分类或账户 |
| 创建/校验/下载备份 | 显示时间、数量、格式、大小、完整性与“未加密”提示 | backup ID、format/schema/app version、profileId、counts、hash、幂等键 | SQLite online backup 产生请求开始时 profile 的一致快照；记账可继续 | staging 深校验后同卷原子发布，不改 ledger/schema | 同 key 重试、并发写、profile 切换、坏 zip/hash、未知格式、磁盘/权限失败 |
| 切换空间 | 一次性切换，不混旧数据 | 目标 profile、旧游标失效 | 活动上下文更新 | 打开独立 ledger.db | 归档空间、目录缺失、catalog 损坏 |
| 切换日/周/月/年与相邻期间 | 标题、值、比较和趋势同步变化 | granularity、anchor、规范 range/asOf | 按发生日或结算日使用正确口径 | 只读，不写计算缓存 | 周/月/年边界、闰年、未来期间、空账本 |
| 新建或修改自定义指标 | 中文公式提示、即时校验和预览 | 稳定引用 token、AST、format、precision、revision | 依赖排序后得到值或明确 dataStatus | definition、formula version、dependency、operation 原子提交 | 重名、坏引用、循环、除零、深度/节点超限、并发冲突 |
| 编辑总览布局 | 拖动/缩放不裁切；保存、取消和重置行为明确 | 12 列坐标、尺寸、min/max、expected revision | 不改变指标和财务事实 | layout 与 items 原子替换 | 重叠、越界、未知 widget、极小尺寸、重复保存 |

### 7.3 数据与行为

- 三类基础记录的金额、余额方向、结算日、分类/账户引用和回收站规则均有 Java 断言；不能只断言“不报错”。
- 新建→展示→服务重启→编辑→重启→删除→余额变化→恢复→余额恢复的最终数值和状态一致，并至少一次走真实浏览器→REST→Java→SQLite 链路。
- 资产、分摊、手工指标数据、报表、预警和旧数据导入没有实现时，界面不显示占位入口，system capabilities 也不宣称支持。
- 默认系统指标、时间边界、发生/结算口径、账户余额方向、百分比零分母、依赖顺序和循环拒绝均有 Java 领域断言。
- 指标或分类/账户显示名改变后，已保存公式仍按稳定 ID 计算；重开数据库后公式版本、当前指针和布局保持一致。

### 7.4 API、安全和可靠性

- 所有 `/api/v1` 财务请求都经过短期浏览器会话认证；变更请求还需 CSRF 凭据。无认证、错认证、跨源和非 loopback 请求均拒绝。该要求已由 P7-004 实现并通过 Java HTTP 负例和隔离真实浏览器闭环验证；P7-003 已从活动服务、Vite 代理、前端会话 client 和构建链清理旧 Bearer 兼容分支。
- Vue 不持有长期密钥；会话 Cookie 为 `HttpOnly`、`SameSite=Strict`、host-only。CSP 和浏览器内容安全策略由 Java 静态资源响应实现。
- 错误不泄漏堆栈、SQL、令牌、账本正文或完整私人路径。
- 写请求使用 `Idempotency-Key`；超时后以同一键重试不重复写入。初始化完成前普通业务 API 返回 `LEDGER_SETUP_REQUIRED`，不只依赖前端隐藏页面。
- 记录、数据版本和幂等结果在同一事务内完成；数据库健康检查包含完整性与外键检查。

### 7.5 性能与运行

- 页面和列表使用有界响应，不因查看单页而加载整个账本。
- 以个人常用数据和交互体验为准；出现可复现的卡顿后再记录数据规模、测量耗时并决定是否优化。
- 当前不定义必须达成的 20,000 条数据压测或分享包验收门槛。
