# LedgerX Java 11 前后端分离重构需求基线

- 状态：已接受，可进入模块规格与任务拆分
- 日期：2026-09-14
- 阶段：架构基线修订；不代表目标实现已经完成
- 现状基线：仓库 v3.1 的 WPF/WebView2 + React/TypeScript + 本地 JSON 实现
- 基础版范围裁决：[ADR-010](./decisions/ADR-010-basic-ledger-scope.md)

## 1. 目标

将 LedgerX 重构为一个本地优先的 Windows 桌面应用。当前交付目标不是完整复制 v3.1，而是先形成可稳定自用和小范围分享的**基础记账版**：

- 后端使用 Java 11，负责基础收支规则、事务、SQLite 和诊断；
- 前端使用 HTML、CSS、JavaScript、Vue 3 和 Vite，负责展示与交互；
- 前后端能够独立启动、构建、测试，通过本机版本化 REST API 协作；
- Electron 作为桌面壳，负责窗口、Java 后端进程生命周期和最小操作系统能力；
- 最终仍是一个安装、一个启动入口、一个本地用户操作的桌面产品，不演变成微服务或云系统。

基础记账版以分类、账户、收入/固定支出/弹性支出、余额、记录编辑和回收站为完整闭环。固定资产、分摊、指标/公式、报表/预警、旧 JSON 导入和应用内备份恢复延后，不阻塞基础版。当前 WPF/React 版本继续作为历史行为参考，不要求基础版逐项等价。

## 2. 规模评估与假设

### 2.1 分类

**产品规模：小型；重构风险：中等。**

运行时虽然有 Electron 与 Java 两个操作系统进程，但它们属于同一安装和同一用户会话。基础收支正确性、数据持久化和跨进程契约需要测试，但没有多人权限、金融合规、独立扩缩容或分布式一致性需求。

### 2.2 维度假设

| 维度 | 当前与可信近期假设 | 设计影响 |
| --- | --- | --- |
| 范围 | 基础记账闭环；高级财务能力延后 | 不以 v3.1 全功能等价阻塞可用版本 |
| 寿命 | 继续维护 3–5 年 | API、schema、备份均显式版本化 |
| 用户/流量 | 单设备、单操作者、可有多个本地用户空间；无公网流量 | 一个 Java 写者足够，不做分布式系统 |
| 数据量 | 常见 1,000–20,000 条记录；基础验收使用 20,000 条 | SQLite + 已有索引 + 游标分页足够 |
| 团队 | 1–3 名维护者，前后端可分别开发 | 同仓库清晰目录和契约测试，不拆多个服务仓库 |
| 部署 | Windows 10/11 x64，离线；个人自用和小范围分享，不作为商业服务发布 | 采用单机包；可选择便携压缩包或 per-user 安装器，不引入服务端、在线更新或企业运维 |
| 安全 | 单机、单用户；不提出金融合规、角色、加密或审计需求 | 只保留已实现的 loopback、会话令牌和 Electron 隔离基线 |
| 集成 | 无第三方在线 API；基础版不需要文件导入、通知或应用内备份 | 不新增 preload 文件能力 |
| 变化频率 | 按个人使用反馈迭代 | Vue 与 Java 独立开发，基础规则只在后端实现 |

## 3. 已确认决定与安全假设

1. Java 11 是后端源码和生产运行时硬约束，编译使用 `--release 11`。
2. 目标前端固定为 Vue 3 + Vite + HTML/CSS/JavaScript；首期不使用 TypeScript、SSR 或 Nuxt。
3. Electron 作为目标桌面壳；它不承载财务业务，也不直接访问 SQLite。
4. 前后端以 `/api/v1` REST/JSON 契约独立开发；开发和生产都由同源入口访问 API。
5. SQLite 替代活动账本 JSON；一次只允许一个 Java 后端写入。
6. 只直接导入 v3.1 `schemaVersion=4` 和备份 `formatVersion=2`；更旧版本先由现有程序升级。
7. 首期仅 CNY、最多两位小数；不提供多币种。
8. 不加入应用锁、数据库加密或加密备份；必须如实说明依赖 Windows 账户和磁盘权限。
9. 备份/恢复以单个用户空间为单位。
10. 界面按功能、内容、核心交互和可访问性等价，不要求与旧 WebView2 像素级一致。
11. 先不考虑 PDF 报表导出，不保留占位按钮或空接口。
12. 当前用户未授权修改业务实现；本轮仅同步需求、架构、接口、模块和任务文档。
13. 产品仅供个人自用和小范围非商业分享；首期不要求购买代码签名证书、应用商店上架、商业支持或在线更新。分享包仍须在干净 Windows 环境完成离线启动、数据持久化和退出无孤儿进程验证；未签名包可能显示 Windows 发布者提示，须在分享说明中如实提示。
14. 基础版只开放 `INCOME`、`FIXED_COST`、`VARIABLE_COST` 三类记录；每条记录必须选择活动分类、活动账户和结算日，统一按 `PAID_FROM_ACCOUNT` 影响账户余额。
15. 基础记录不接收或返回资产、分摊、指标归集、应付款、批量永久清理字段或 endpoint。相关数据库表可保留为空，不能因此阻塞基础记录实现。
16. 不为本项目引入金融安全或金融合规需求：不做角色权限、审批、操作审计、数据库/备份加密、反欺诈、监管报送或交易级风控。已存在的本机 REST 会话保护属于桌面进程隔离，继续保留但不扩展。
17. 基础版的数据备份方式为：完全退出 LedgerX 后复制整个 `%LocalAppData%\LedgerX` 目录；恢复时也必须在应用完全退出后整体替换。应用内备份/恢复和旧 JSON 导入属于后续可选能力。

## 5. 范围

### 5.1 包含

- Java 11 模块化单体后端及独立 Maven 构建。
- Vue 3/JavaScript 前端及独立 npm 构建、测试和浏览器开发模式。
- Electron 主进程/preload、安全窗口和 Java 子进程管理。
- 本机 `127.0.0.1` REST API、认证令牌、版本、错误、分页、幂等和并发契约。
- 用户空间、设置、分类和账户管理。
- 收入、固定支出、弹性支出的新增、查询、编辑、移入回收站和恢复，以及账户余额重算。
- SQLite 事务、约束、索引、schema history 和健康检查。
- 共享 JSON fixtures、Java API 集成测试、Vue 测试和真实 Electron→HTTP→Java→SQLite E2E。
- 手工数据目录备份/恢复说明，以及个人分享包的构建和启动说明。

### 5.2 非目标

- 云同步、远程服务器、移动端、网页登录、多人协作或远程访问本机 API。
- 微服务、消息队列、事件总线、通用插件框架、ORM、依赖注入容器或服务发现。
- 银行/支付/券商/行情/OCR/AI 在线集成。
- SSR、Nuxt、前端直接 Node.js/SQLite 访问，或在 Electron renderer 中启用 Node integration。
- 预算、转账、应付款、固定资产、成本分摊、指标/公式、仪表盘、报表、预警、CSV/旧 JSON 导入、多币种、附件、税务等高级能力。
- 任意 JavaScript/SQL 公式。
- PDF 报表导出。
- 应用内备份/恢复、自动备份、保护快照、主题导入/导出。
- 金融合规、角色权限、审批、操作审计、数据库加密、加密备份、反欺诈或监管报送。
- Java 与旧 C# 同时写入同一活动数据，或 Java 数据反向同步旧 JSON。

## 6. 核心用户流程

### 6.1 启动

1. 用户启动 LedgerX。
2. Electron 取得单实例控制，生成本次会话令牌，解析 `%LocalAppData%\LedgerX` 作为本次桌面会话的唯一数据根并传给打包的 Java 后端；仅隔离测试可覆盖该根。
3. Java 校验启动令牌和必要配置，只绑定 `127.0.0.1` 的临时端口；开始监听后立即报告一次传输就绪端口。该信号只表示 HTTP 可连接，不表示数据库或业务已经就绪。
4. Electron 校验端口并注册会话认证，然后调用已认证的启动状态 API；该 API 是应用 `STARTING`、`READY` 或恢复状态的唯一判定依据。
5. Electron 加载由 Java 同源提供的 Vue 静态资源。`STARTING` 显示初始化页且禁用业务操作，`READY` 进入活动空间，恢复或失败状态显示可操作恢复页，不出现空白窗口。

### 6.2 前后端独立开发

1. 前端开发者单独启动 Vue/Vite；Vite 将 `/api` 代理到 Java 开发实例。
2. 后端开发者单独启动 Java，以 API fixtures/集成测试验证契约，不依赖 Electron UI。
3. 双方只依赖 `docs/api.md`、具体 API 文档和共享 fixtures；不得通过导入对方内部类或数据库表耦合。

### 6.3 记录与重载

1. 用户填写记录并提交；Vue 发送精确金额、业务日期、引用 ID、幂等键和并发版本。
2. Java 校验分类、账户、日期和金额，在一个 SQLite 事务内保存一条 `finance_record`，同时更新数据版本和幂等结果；基础版不写资产、分摊或指标表。
3. 返回创建结果、实体版本和数据版本；Vue 更新记录列表和账户余额。
4. 关闭并重启后，记录和余额保持一致。

### 6.4 编辑、删除和恢复

- 编辑使用乐观并发版本；冲突时不覆盖较新数据。
- 普通删除进入回收站并可恢复；基础版不提供永久清理或批量删除。
- 失败时事务回滚并给出稳定错误码，不出现半保存。

### 6.5 手工备份与恢复

- 用户完全退出 LedgerX，确认 Electron 和 Java 进程已结束，然后复制整个 `%LocalAppData%\LedgerX` 目录到个人选择的位置。
- 需要恢复时，在应用退出状态下先保留当前目录副本，再用完整备份目录整体替换；不支持只复制某个运行中的 `ledger.db`。
- 该流程由用户文档说明，不新增 HTTP endpoint、上传协议或文件桥接。

## 7. 可验证验收标准

### 7.1 架构与独立开发

- `frontend/` 能单独执行安装、开发、构建和前端测试，不编译 Java 或 Electron；旧 `web/` 保留为迁移对照直到验收。
- Java 后端能单独执行编译、单元和 API 集成测试，不启动浏览器或 Electron。
- Electron 只通过公开 API/preload 契约连接两端；renderer 不导入 Java 类、不读取数据库、不调用 Node.js 通用 API。
- 生产包不存在 JavaFX/WebView bridge 运行依赖；旧实现仅作为迁移和对照基线。

### 7.2 跨层验收矩阵

| 用户操作 | 前端反馈 | 跨层字段 | 业务结果 | 持久化结果 | 边界 |
| --- | --- | --- | --- | --- | --- |
| 启动应用 | 加载态后进入主页或恢复页 | request ID、API/应用/schema 版本 | 仅一个后端会话可写 | 打开活动 profile | 后端超时、端口占用、坏库、窗口重载 |
| 新建/编辑记录 | 成功后列表和账户余额更新；错误就地显示 | amount/currency、occurredOn、recordType、categoryId、accountId、settlementOn、note、revision、幂等键 | 收入增加资产账户余额、支出减少；负债账户方向相反 | record、dataRevision、operation 同事务提交 | 空值、零/负金额、归档引用、重复提交、冲突 |
| 删除/恢复 | 回收站状态明确，余额随最终状态变化 | ID、If-Match、幂等键 | 删除取消余额影响，恢复重新计入 | `deleted_at` 与 revision 持久化 | 重复删除/恢复、归档分类或账户 |
| 手工备份/恢复 | 文档能指导用户完成关闭、复制、替换和重开 | 无 API 字段 | 不涉及运行中业务处理 | 整个 LedgerX 数据目录被复制/整体恢复 | 应用未退出、备份不完整、恢复前未保留当前副本 |
| 切换空间 | 一次性切换，不混旧数据 | 目标 profile、旧游标失效 | 活动上下文更新 | 打开独立 ledger.db | 归档空间、目录缺失、catalog 损坏 |

### 7.3 数据与行为

- 三类基础记录的金额、余额方向、结算日、分类/账户引用和回收站规则均有 Java 断言；不能只断言“不报错”。
- 新建→展示→重启→编辑→重启→删除→余额变化→恢复→余额恢复的最终数值和状态一致，并至少一次走真实 Electron→REST→Java→SQLite 链路。
- 资产、分摊、指标、报表、预警和旧数据导入没有实现时，界面不显示占位入口，system capabilities 也不宣称支持。

### 7.4 API、安全和可靠性

- 所有 `/api/v1` 请求都经过桌面会话 Bearer 认证；无认证、错认证和非 loopback 请求均拒绝。
- Electron renderer 不持有令牌，不启用 Node integration；CSP、导航、新窗口和权限默认拒绝。
- 错误不泄漏堆栈、SQL、令牌、账本正文或完整私人路径。
- 写请求使用 `Idempotency-Key`；超时后以同一键重试不重复写入。
- 记录、数据版本和幂等结果在同一事务内完成；数据库健康检查包含完整性与外键检查。

### 7.5 性能与发布

- 在普通 Windows 11 x64 设备和 20,000 条记录样本上，冷启动到可交互暂定不超过 5 秒。
- 常用记录列表和账户读取 P95 暂定不超过 500 ms；单笔写入 P95 暂定不超过 300 ms。
- 列表默认 50、最大 200；长任务不阻塞 Electron renderer 或 Java HTTP 接收线程。
- 发布包断网可启动，自带兼容 Electron、Vue 资源、Java 11 runtime 和后端；关闭桌面应用后 Java 子进程不会遗留。

## 8. 本轮完成定义

架构设计阶段已废止旧 JavaFX/进程内 bridge 计划；S0-001..006 的实现与隔离测试证据仍保留。当前“前后端分离基座”已在用户授权的本机 Node 24.19.0 环境验证。基础记账版仍需依次完成 P3 分类/账户、P4 基础记录和一次真实桌面闭环；资产、指标、旧数据迁移及商业发布审计不再是该完成定义的一部分。

## 9. 仍需用户决定

基础记账版没有产品范围待决项。Node 24.19.0 是用户明确允许的当前开发/验收环境；不再以 Node 22 复测阻塞开发。Forge 6.4.2 的既有审计风险只需在分享说明中披露，不作为个人自用基础功能的编码门禁。分享包形式和 Java runtime 仍在实际打包前决定。

## 10. 可继续细化或实现的模块

基础版继续实施 `ledger-records` 与 `ui-integration`，并按 `docs/tasks/README.md` 的 P3→P4 顺序执行。`allocation-assets`、`metrics-formulas`、`reports-warnings`、`backup-recovery` 和旧数据迁移均标记为后续可选模块，只有用户以后明确需要时才重新设计和拆分。
